## Intuition

A deterministic verifier answers one question without asking a model for its opinion:
*after this sequence of user actions and this much time, is the program in the state the
request implies?* Thirteen recent papers build such verifiers for generated web pages, games
and 3D scenes. Each reads the program through a different keyhole — pixels, the
<Term def="Document Object Model: the browser's live tree of elements that any script can query">DOM</Term>,
a state object the program was told to expose — and each pays for its keyhole somewhere:
brittle selectors, a model in the loop, or a spec the program must obey to the letter.

The proposal here is to stop treating GUIs, games and simulations as different things. All
three are the same object: a <Term def="a process whose next state depends on its current state and an incoming event">driven process</Term>
with **state**, a vocabulary of **actions**, a **clock**, a source of **randomness**, and a
picture that is a pure function of state. Front-end engineering settled on exactly this shape
years ago — Redux reducers, Elm's `update`/`view`, React Testing Library's "test like a user"
queries, Playwright's fake clock — and its test tools are the most mature deterministic
verifiers of interactive behavior that exist. The verifier below borrows their interaction
model and adds what generated code needs: a contract the checker can rely on, rules written
from the request before any code exists, and a way to find rules nobody wrote.

## 1. What makes an interactive artifact hard to verify

Four properties, each of which breaks a familiar tool.

| Property | What it breaks | Example |
|---|---|---|
| **It remembers.** Correctness is a predicate over *sequences* of actions, not one input–output pair. | unit tests | after `setK(2)` then `reset()`, `k` must be 1 again |
| **It runs on its own.** Time and randomness are inputs the tester did not choose. | golden outputs, screenshots | a Flappy Bird whose pipes spawn at random; a timer |
| **Its output is a picture.** The observable surface is pixels, not data. | assertions | a canvas plot — nothing to query |
| **It may be built many ways.** The same request admits many correct programs. | selector-bound scripts | `#category-select-id` exists in one implementation of ten |

Every existing verifier is a choice of which of these four to solve and which to pay for.

## 2. How the existing verifiers are designed

Read along five axes — what the check *reads*, who *writes* it and when, what it *binds* to,
who owns *time*, and whether a *model* still decides — the thirteen fall into five families.

| Family | Papers | Reads / binds to | Who writes checks | Time | Model in verdict | Where it breaks |
|---|---|---|---|---|---|---|
| **A · Hooks by fiat** | FrontendBench, Web-Bench, InteractScience | DOM via ids/classes the prompt dictates | humans or an LLM offline, hidden | none | none (InteractScience's visual half: VLM) | coupling imposed and never measured; a correct page built differently fails |
| **B · Requirement contracts run on the live page** | WebRISE, [WebGrader](../../papers/arxiv-2608.06474/) | DOM re-grounded by role/text at run time | LLM from the requirement, *before* seeing the page (WebGrader); offline + human check (WebRISE) | settle delays, timeouts | **an LLM agent executes and an LLM judges** every assertion | neutrality bought with a model: WebGrader judges at plan, ground and verdict; WebRISE misses 9 of 25 injected defects |
| **C · State interface required of the program** | [WorldCoder-Bench](../../papers/arxiv-2606.01869/), GameXpert/GameFix, [InfiniteWeb](../../papers/arxiv-2601.04126/), [AutoWebWorld](../../papers/arxiv-2602.14296/) | `window.__3D_STATE__`; JSON snapshots; `localStorage` keys; an FSM the site was generated from | experts, hidden (WorldCoder); the *same* LLM that wrote the site (InfiniteWeb); nobody checks site-vs-FSM (AutoWebWorld) | **fixed timestep** in the prompt (WorldCoder); **virtual clock** + zero-flake gate (GameFix) | none | the interface is a new failure mode — schema drift is 42.8 % of WorldCoder failures; a benchmark can score that, a harness must repair it |
| **D · State injection** | [GameGen-Verifier](../../papers/arxiv-2605.07442/) | game state patched in through the runtime, screenshots + logs out | LLM keypoints `(P, a, Q)` grounded on the source | isolated instance per check | **VLM primary**, assertions when possible | reaching a precondition costs nothing, but the verdict is a picture read by a model; recall 1.0 / precision 0.91 = every error is a missed defect |
| **E · Task-agnostic probes** | I-WebGenBench, [HTMLCure](../../papers/arxiv-2605.26807/), VISTA | click every control, watch for any DOM mutation; geometry (IoU) | nobody per task | none | HTMLCure: VLM 20/100; I-WebGenBench: 95/100 | nothing coupled, nothing *asserted* — HTMLCure's interactivity score is ≈1.1/10 for every model |

Two patterns cut across the families. **Requirement-first authorship** (WebGrader's planner
never sees the site; WorldCoder's contracts are hidden) is what keeps a check honest; checks
written *with* the implementation, by the same model (InfiniteWeb), have no independent
oracle. And **the verifier is rarely verified**: only WorldCoder mutation-hardens its
contracts, only WebRISE and WebGrader inject faults, only four papers report agreement with
humans, and none reports all three.

The gap: nobody writes checks *at generation time for an unseen request*, validates them,
and keeps a model out of the verdict. That is the corner to occupy — but only with a design
that beats each family on its own axis.

## 3. What software testing already solved

The deterministic-verification problem is old in one industry. Its answers:

- **Test like a user, query by meaning.** Testing Library's rule: "your test should resemble
  how users interact with your code," and its query priority puts `getByRole` first and
  `getByTestId` last. A control is found by *role and accessible name* ("slider named k"),
  never by class or id — the anti-selector principle, made precise.
- **Interaction is an event *sequence*, not a call.** `user-event` dispatches what a real
  click dispatches — pointer down, focus, pointer up, click — so wiring bugs surface.
- **Settle before you assert.** React's `act()` flushes pending updates and effects; Playwright
  locators auto-wait for actionability (attached, visible, stable, enabled) and its
  assertions retry. Flakiness is a missing settle step, not fate.
- **Own the clock.** Playwright's `page.clock` replaces `Date`, `setTimeout`, `setInterval`,
  `requestAnimationFrame` and `performance`, with `install`, `runFor`, `fastForward`,
  `pauseAt`, `setFixedTime`. Games learned the same lesson as *fix your timestep* and
  *deterministic replay*: seed plus input log reproduces the run byte for byte.
- **State changes only through actions.** Redux (`reducer(state, action) → state'`) and Elm
  (`update`, `view = f(model)`) make the program a driven process by construction; a test is
  "dispatch, then assert on state," and the view is a pure function that can be snapshotted.
- **Generate the sequences from a model.** XState's test model walks a statechart and asserts
  per state; `fast-check` `commands` / Hypothesis rule-based state machines run *random*
  command sequences with preconditions against a model and the real system, then **shrink**
  a failure to the shortest sequence that reproduces it.
- **When there is no oracle, use relations.**
  <Term def="testing without an exact expected output: check relations between outputs of related inputs (Chen et al., 1998)">Metamorphic testing</Term>
  — doubling the input doubles the peak; reversing the list reverses the result — is how
  numerical and simulation code is tested.

None of these tools assumes the program was written by a model, so none asks the program to
carry a contract or writes the tests from a request. That is the part we add.

## 4. One interaction model for GUI, game and simulation

<Definition term="Interactive artifact as a driven process">
An artifact is <M tex="\langle S, s_0, A, \mathrm{step}, \mathrm{render} \rangle" />: a state space <M tex="S" /> with initial state <M tex="s_0" />; a finite vocabulary of named, typed **actions** <M tex="A" />; a transition function
<MathBlock>{`s' = \\mathrm{step}(s,\\; e,\\; \\omega), \\qquad e \\in A \\cup \\{\\mathrm{tick}(\\Delta t)\\},\\; \\omega \\sim \\mathrm{host}`}</MathBlock>
driven by events from three sources — the **user** (<M tex="a \in A" />), the **clock** (<M tex="\mathrm{tick}" />), and the **environment** (random draws <M tex="\omega" />, supplied by the host); and a pure **render** <M tex="\mathrm{render}: S \to \mathrm{View}" />. A **run** is <M tex="s_0 \xrightarrow{e_1} s_1 \xrightarrow{e_2} \cdots" />. Every "does it work?" question is a predicate over runs.
</Definition>

A slider-driven plot, a Flappy Bird and a pendulum simulator are all instances: the
actions are `setK`/`reset`, `flap`, `setLength`/`pause`; the clock drives the plot not at all,
the bird every frame, the pendulum every physics step; randomness enters only the game.

The model gives three **layers** at which the verifier can interact, mirroring how a user,
a framework and a device see the program:

| Layer | What it is | Verifier uses it for | Precedent |
|---|---|---|---|
| **L0 · semantic actions** | `dispatch("setK", {k: 2})` — what the program *means* to do | rule checks: fast, exact, implementation-neutral by naming | Redux actions, GameGen keypoints, WorldCoder's scripted actions |
| **L1 · user intents on the surface** | "move the slider named *k* to 2", "press *Checkout*" — resolved by role and accessible name | **wiring** checks: does the user-level path produce the same transition as the semantic action? | Testing Library `getByRole` + `user-event` |
| **L2 · raw device events** | pointer at (x, y), key code | only where no surface exists (a canvas game), through a declared input map | Playwright, game input replay |

The **contract** is the set of ports that make the three layers and the three event sources
reachable from outside the program:

```
getState() → data              // observable state, schema-declared
setState(s)                    // injection and restore (preconditions, replay)
actions = [{name, params}]     // the vocabulary; dispatch(name, params)
tick(dt)                       // the host owns time
random()                       // the host owns randomness (seeded)
surface() → {role, name, value, …}   // the queryable rendered tree; on canvas, a declared overlay
render = f(state)              // same state ⇒ same picture (checked by remount + snapshot)
```

This is [state-contract verification](../state-contract-verification/) with two additions
the existing contracts lack: **actions by name** (WorldCoder scripts raw events; InfiniteWeb
reads storage after the fact) and a **queryable surface** (so wiring can be verified without
pixels). Host-owned `tick` and `random` generalize WorldCoder's prompt-prescribed timestep and
GameFix's virtual clock into something the checker controls rather than requests.

## 5. The verifier built on the model

**Rules.** Six kinds, all predicates over runs, all written from the *request* before any
candidate exists (WebGrader's requirement-first principle):

1. **Conformance** — the contract is present and schema-valid; every declared action is
   dispatchable; `render` is deterministic (remount with the same state, identical snapshot);
   no wall-clock or `Math.random` reachable (host shims throw). This is the layer where
   WorldCoder's 42.8 % schema drift lands — as a *repairable* verdict, not a score of zero.
2. **Action rules** `{P} a {Q}` — GameGen's keypoints: `setK(2) ⇒ k = 2 ∧ peak = 2·base`.
3. **Invariants** over every state of every run — `total = Σ price · checked`.
4. **Temporal rules** over ticks — "after 30 ticks with no input the bird's y decreases";
   debounce and timer behavior become countable.
5. **Metamorphic relations** for continuous state, where no exact oracle exists —
   scaling, symmetry, monotonicity, conservation, idempotence, commutativity of independent
   actions. No verifier in §2 has these; WorldCoder and GameFix stop at tolerance bands.
6. **Wiring and persistence** — every L1 intent equals its L0 action; `reload` preserves
   state; `reset` returns to <M tex="s_0" />.

**Sequences.** Three generators, budgeted together: (a) **model-based** — the rules induce a
statechart; cover every transition (WebRISE's ICG, XState); (b) **property-based** — seeded
random walks over `A ∪ {tick}` with preconditions, **shrunk** to the minimal failing sequence
(fast-check / Hypothesis); (c) **replay** — seed + input log reproduces any run exactly.

**Rule admission.** A rule set is trusted only after it rejects mutants of the first passing
candidate — [mutation-hardened checks](../mutation-hardened-checks/), WorldCoder's admission
criterion turned into a pipeline step. Rules that never fail a mutant are flagged as vacuous.

**Determinism.** Host clock and seeded randomness; an `act()`-style settle after every event
(flush microtasks, effects, animation frames); fresh instance or `setState` restore per check;
an N-run identical-trajectory gate (GameFix's zero-flake rule) before a verdict counts.

**Verdict.** Per rule: PASS · FAIL · SKIPPED (precondition unreachable — an upstream defect,
counted once, as in WebRISE) · UNSUPPORTED (action not declared). A FAIL carries the shrunk
sequence and the state diff, which names the action whose post-state first diverged — the
handler to fix. A verdict is a *localizer*, not a score band.

**Rules nobody wrote.** Generate several candidates; where all pass the rules but diverge
under the same sequence, the rules are silent — [differential testing](../differential-testing/)
adds the rule or asks the user. This is the only mechanism in the table that can extend an
incomplete rule set; GameGen's recall 1.0 against raters who share its blind spots shows why
one is needed.

## 6. Why this beats each family on its own axis

| Family | Their axis | This design |
|---|---|---|
| A · hooks by fiat | coupling by ids | binds to action *names* and role/name on the surface; coupling is measured, not assumed |
| B · live-page contracts | implementation-neutral but model-judged | L0 `dispatch` replaces the executing agent; data predicates replace the judge; zero model calls in a verdict |
| C · state interface | schema + fixed timestep, checks hidden and hand-written | adds actions, host clock/random, injection, wiring, metamorphic rules; checks written at generation time and mutation-admitted; conformance repaired rather than failed |
| D · injection | reachability solved, verdict by VLM | `setState` is injection by contract; the outcome is read as data |
| E · probes | zero coupling, zero discrimination | probes become the conformance layer; the request-derived rules supply discrimination |

## 7. Decisions to make together

1. **Action granularity.** Coarse semantic actions (`setK`) or fine ones (`dragStart`,
   `dragMove`)? Who fixes the vocabulary — the rule-writer from the request, or the generator?
2. **Canvas surfaces.** Require a declared semantic overlay (hit regions with roles) so L1
   wiring checks work on games and plots, or accept L2 + input map only? The former costs
   generation quality — WorldCoder's schema-drift rate is the warning.
3. **What stays outside.** Aesthetics and layout taste are not rules; `render = f(state)` plus
   snapshot equality is all the verifier says about pictures. Agree, or keep a separate
   visual judge outside the loop?
4. **How much host control a platform will accept.** Shimming the clock and randomness is a
   runtime change; Artifacts-style platforms already dictate the framework, so it is realistic
   there — is it acceptable everywhere we want to evaluate?
5. **Mutation operators** for UI/game/sim code: stale-state, swapped handler, wrong sign,
   dropped redraw, off-by-one tick — which set makes admission meaningful without being
   tailored to our own bugs?
6. **The metamorphic library.** Which relations generalize across plots, games and
   simulations, and how does the rule-writer pick them from a request?
7. **Budget split** between model-based coverage and random walks, and the shrinking cost.
8. **Accessibility as a requirement.** L1 needs roles and names on controls. Requiring them of
   generated code is a constraint — and an accessibility win. Do we require or reward it?
9. **Localization heuristic.** "First action whose post-state violates a rule" versus delta
   debugging over the sequence.
10. **The testbed.** Computable Canvas components already expose `getState`/`setState`; the
    contract adds `actions`/`dispatch`, `tick`/`random`, and `surface`. Which come first?

## In the papers

WorldCoder-Bench supplies the state schema, the prescribed timestep and mutation-hardening;
GameGen-Verifier the `(P, a, Q)` rule shape and state injection; GameFix the virtual clock,
tolerance bands and the zero-flake gate; WebRISE the requirement-induced statechart and
SKIPPED-vs-FAIL attribution; WebGrader requirement-first planning and the fault-set verifier
benchmark; InfiniteWeb instrumentation variables and dense per-rule reward; AutoWebWorld the
FSM-as-generator idea and its unclosed conformance gap; HTMLCure verdict-routed repair and
regression-penalized acceptance; FrontendBench and InteractScience the cost of ids by fiat;
VISTA partial credit by geometry and a principled refusal of LLM judges; I-WebGenBench the
task-agnostic probe as a floor.

## Pitfalls / open questions

- A contract shifts failure from "wrong behavior" to "wrong interface"; a verifier that only
  scores conformance has moved the problem, not solved it. The harness must repair conformance.
- Rules written from an ambiguous request are ambiguous rules; differential testing exposes
  the gap but cannot resolve it without the user.
- Metamorphic relations can be vacuously true (a plot that ignores `k` satisfies "doubling
  k doubles the peak" if the peak is 0). Mutation admission is the guard.
- Deterministic replay hides timing bugs that only wall-clock scheduling produces; report
  it as a scope limit, not a solved problem.
