## Intuition

A deterministic verifier answers one question without asking a model for its opinion:
*after this sequence of user actions and this much time, is the program in the state the
request implies?* Thirteen recent papers build such verifiers for generated web pages, games
and 3D scenes. Each reads the program through a different keyhole — pixels, the
<Term def="Document Object Model: the browser's live tree of elements that any script can query">DOM</Term>,
a state object the program was told to expose — and each pays for its keyhole somewhere:
brittle selectors, a model in the loop, or a spec the program must obey to the letter.

This page stops treating GUIs, games and simulations as different things. All three are the
same object: a <Term def="a process whose next state depends on its current state and an incoming event">driven process</Term>
with **state**, a vocabulary of **actions**, a **clock**, a source of **randomness**, and a
picture that is a pure function of state. Front-end engineering settled on that shape years
ago — Redux reducers, Elm's `update`/`view`, Testing Library's role queries, Playwright's fake
clock — and its test tools are the most mature deterministic verifiers of interactive
behavior in existence. The design below borrows their interaction model and adds what
generated code needs: a contract the checker can rely on, rules written from the request
before any code exists, and — because the same agent writes the code *and* the checks —
mechanisms that keep those checks honest.

## 1. What makes an interactive artifact hard to verify

| Property | What it breaks | Example |
|---|---|---|
| **It remembers.** Correctness is a predicate over *sequences* of actions. | unit tests | after `setK(2)` then `reset()`, `k` must be 1 again |
| **It runs on its own.** Time and randomness are inputs the tester did not choose. | golden outputs, screenshots | pipes that spawn at random; a timer |
| **Its output is a picture.** The observable surface is pixels, not data. | assertions | a canvas plot — nothing to query |
| **It may be built many ways.** One request admits many correct programs. | selector-bound scripts | `#category-select-id` exists in one implementation of ten |

Every existing verifier chooses which of the four to solve and which to pay for.

## 2. How the existing verifiers are designed

Read along five axes — what a check *reads*, who *writes* it and when, what it *binds* to,
who owns *time*, and whether a *model* still decides — the thirteen fall into five families.

| Family | Papers | Reads / binds to | Who writes checks | Time | Model in verdict | Where it breaks |
|---|---|---|---|---|---|---|
| **A · Hooks by fiat** | FrontendBench, Web-Bench, InteractScience | DOM via ids/classes the prompt dictates | humans or an LLM offline, hidden | none | none (InteractScience's visual half: VLM) | coupling imposed and never measured; a correct page built differently fails |
| **B · Requirement contracts on the live page** | WebRISE, [WebGrader](../../papers/arxiv-2608.06474/) | DOM re-grounded by role/text at run time | LLM from the requirement, *before* seeing the page (WebGrader); offline + human check (WebRISE) | settle delays, timeouts | **an LLM agent executes, an LLM judges** every assertion | neutrality bought with a model; WebRISE misses 9 of 25 injected defects |
| **C · State interface required of the program** | [WorldCoder-Bench](../../papers/arxiv-2606.01869/), GameXpert/GameFix, [InfiniteWeb](../../papers/arxiv-2601.04126/), [AutoWebWorld](../../papers/arxiv-2602.14296/) | `window.__3D_STATE__`; JSON snapshots; `localStorage` keys; an FSM the site was generated from | experts, hidden (WorldCoder); the *same* LLM that wrote the site (InfiniteWeb); nobody checks site-vs-FSM (AutoWebWorld) | **fixed timestep** in the prompt (WorldCoder); **virtual clock** + zero-flake gate (GameFix) | none | the interface is a new failure mode — schema drift is 42.8 % of WorldCoder failures; a benchmark scores it, a harness must repair it |
| **D · State injection** | [GameGen-Verifier](../../papers/arxiv-2605.07442/) | state patched in through the runtime; screenshots + logs out | LLM keypoints `(P, a, Q)` grounded on the source | isolated instance per check | **VLM primary**, assertions when possible | preconditions cost nothing to reach, but a model reads the outcome; recall 1.0 / precision 0.91 means every error is a missed defect |
| **E · Task-agnostic probes** | I-WebGenBench, [HTMLCure](../../papers/arxiv-2605.26807/), VISTA | click every control, watch for any DOM mutation; geometry | nobody per task | none | HTMLCure 20/100; I-WebGenBench 95/100 | nothing coupled, nothing *asserted* — HTMLCure's interactivity score is ≈1.1/10 for every model |

Two patterns cut across the families. **Requirement-first authorship** — WebGrader's planner
never sees the site, WorldCoder's contracts are hidden — is what keeps a check honest; checks
written *with* the implementation by the same model (InfiniteWeb) have no independent oracle.
And **the verifier is rarely verified**: only WorldCoder mutation-hardens its contracts, only
WebRISE and WebGrader inject faults, only four papers report agreement with humans, none does
all three.

The gap: nobody writes checks *at generation time for an unseen request*, validates them, and
keeps a model out of the verdict. That corner is empty — but it is only worth occupying with a
design that beats each family on its own axis (§6).

## 3. What software testing already solved

- **Test like a user, query by meaning.** Testing Library's rule — "your test should resemble
  how users interact with your code" — puts `getByRole` first and `getByTestId` last: a
  control is found by *role and accessible name* ("the slider named k"), never by class or id.
- **An interaction is an event sequence, not a call.** `user-event` dispatches what a real
  click dispatches — pointer down, focus, pointer up, click — so wiring bugs surface.
- **Settle before you assert.** React's `act()` flushes pending updates; Playwright locators
  auto-wait for actionability and its assertions retry. Flakiness is a missing settle step.
- **Own the clock.** Playwright's `page.clock` replaces `Date`, timers, `requestAnimationFrame`
  and `performance` (`install`, `runFor`, `fastForward`, `pauseAt`). Games learned the same
  lesson as *fix your timestep* and *deterministic replay*: seed + input log reproduces a run.
- **State changes only through actions.** Redux (`reducer(state, action) → state'`) and Elm
  (`update`, `view = f(model)`) make a program a driven process by construction; a test is
  "dispatch, then assert on state", and the view can be snapshotted.
- **Generate sequences from a model.** XState's test model walks a statechart; `fast-check`
  commands and Hypothesis rule-based state machines run *random* command sequences with
  preconditions and **shrink** a failure to the shortest sequence that reproduces it.
- **Without an oracle, use relations.**
  <Term def="testing without an exact expected output: check relations between outputs of related inputs (Chen et al., 1998)">Metamorphic testing</Term>
  — doubling the input doubles the peak — is how numerical and simulation code is tested.

None of these assumes the program was written by a model, so none asks it to carry a contract
or derives the tests from a request. That is what we add.

## 4. One interaction model for GUI, game and simulation

<Definition term="Interactive artifact as a driven process">
An artifact is <M tex="\langle S, s_0, A, \mathrm{step}, \mathrm{render} \rangle" />: a state space <M tex="S" /> with initial state <M tex="s_0" />; a finite vocabulary of named, typed **actions** <M tex="A" />; a transition function
<MathBlock>{`s' = \\mathrm{step}(s,\\; e,\\; \\omega), \\qquad e \\in A \\cup \\{\\mathrm{tick}(\\Delta t)\\},\\; \\omega \\sim \\mathrm{host}`}</MathBlock>
driven by events from three sources — the **user** (<M tex="a \in A" />), the **clock** (<M tex="\mathrm{tick}" />) and the **environment** (random draws <M tex="\omega" />, supplied by the host); and a pure **render** <M tex="\mathrm{render}: S \to \mathrm{View}" />. A **run** is <M tex="s_0 \xrightarrow{e_1} s_1 \xrightarrow{e_2} \cdots" />; every "does it work?" question is a predicate over runs.
</Definition>

**Generality comes from the ports, not from the artifact type.** The verifier touches nothing
but the ports below, so a GUI, a game and a simulation differ only in how each port is
*bound* to its runtime — one verifier, three bindings:

| Port | GUI (DOM) | Game (canvas / WebGL) | Simulation / plot |
|---|---|---|---|
| `getState` · `setState` | the app store | entity state: bird, pipes, score | parameters + integrator state |
| `actions` · `dispatch` | handlers: `addItem`, `uncheck` | input commands: `flap`, `moveLeft` | `setK`, `step`, `pause`, `reset` |
| `tick(dt)` | animations, debounce — rarely | every frame, fixed `dt` | every physics step |
| `random()` | seldom | spawns, drops | stochastic models |
| `surface()` | the accessibility tree — free | a declared overlay: HUD, hit regions | the controls (DOM), or an overlay |
| `render = f(state)` | DOM + CSS | the canvas frame | the SVG plot |

The model also gives three **layers** at which a verifier can interact — how a framework, a
user and a device see the program:

| Layer | What it is | Verifier uses it for | Precedent |
|---|---|---|---|
| **L0 · semantic actions** | `dispatch("setK", {k: 2})` — what the program *means* to do | rule checks: exact, fast, neutral by naming | Redux actions, GameGen keypoints |
| **L1 · user intents on the surface** | "move the slider named *k* to 2", resolved by role and name | **wiring** checks: does the user path produce the same transition as the action? | Testing Library + `user-event` |
| **L2 · raw device events** | pointer at (x, y), key code | only where no surface exists, through a declared input map | Playwright, game input replay |

The **contract** is the set of ports that make the layers and the three event sources
reachable from outside:

```
getState() → data              // observable state, schema-declared (may be partial, coverage declared)
setState(s)                    // injection and restore: preconditions, replay
actions = [{name, params}]     // the vocabulary; dispatch(name, params)
tick(dt)                       // the host owns time
random()                       // the host owns randomness (seeded)
surface() → {role, name, value, …}   // the queryable rendered tree; on canvas, a declared overlay
render = f(state)              // same state ⇒ same picture (remount + snapshot)
```

The ports do not all cost the generator the same. `tick` and `random` are **imposed**: host
shims replace `Date`, timers, `requestAnimationFrame` and `Math.random`, as Playwright's clock
does, so a program cannot drift from them — WorldCoder's `clock.getDelta()` failure becomes
impossible rather than penalized. `surface` and `render` are **free** on the DOM. Only
`getState`/`setState` and `actions`/`dispatch` need the program's cooperation, and because
the agent writes the program against this SDK, conformance is the first rule it runs and
repairs — not a hidden schema it is scored against once (the fix for WorldCoder's 42.8 %
schema drift). A wrapped library — a physics engine, GeoGebra — may not expose every internal:
the contract admits **partial state with declared coverage**, and rules may quantify only
over declared fields. This is [state-contract verification](../state-contract-verification/)
with two ports existing contracts lack, **actions by name** and a **queryable surface**.

## 5. The verifier built on the model

**Rules.** Six kinds, all predicates over runs, all written from the *request* before any
candidate exists:

1. **Conformance** — the contract is present and schema-valid; every declared action is
   dispatchable; `render` is deterministic (remount with the same state, identical snapshot);
   no wall clock or `Math.random` is reachable.
2. **Action rules** `{P} a {Q}` — GameGen's keypoints: `setK(2) ⇒ k = 2 ∧ peak = 2·base`.
3. **Invariants** over every state of every run — `total = Σ price · checked`.
4. **Temporal rules** over ticks — "after 30 ticks with no input the bird's y decreases".
5. **Metamorphic relations** for continuous state, where no exact oracle exists — scaling,
   symmetry, monotonicity, conservation, idempotence, commutativity of independent actions.
   No verifier in §2 has these; WorldCoder and GameFix stop at tolerance bands.
6. **Wiring and persistence** — every L1 intent equals its L0 action; `reload` preserves
   state; `reset` returns to <M tex="s_0" />.

**Sequences.** Three generators on one budget: **model-based** — the rules induce a
statechart; cover every transition (WebRISE's ICG, XState); **property-based** — seeded
random walks over `A ∪ {tick}` with preconditions, **shrunk** to the minimal failing
sequence; **replay** — seed + input log reproduces any run exactly.

**Determinism.** Host clock and seeded randomness; an `act()`-style settle after every event;
fresh instance or `setState` restore per check; an N-run identical-trajectory gate (GameFix's
zero-flake rule) before a verdict counts.

**Verdict.** Per rule: PASS · FAIL · SKIPPED (precondition unreachable — an upstream defect,
counted once, as in WebRISE) · UNSUPPORTED (action or field not declared). A FAIL carries the
shrunk sequence and the state diff, which names the action whose post-state first diverged —
the handler to fix. A verdict is a *localizer*, not a score band.

**Rules nobody wrote.** Generate several candidates; where all pass the rules but diverge
under the same sequence, the rules are silent — [differential testing](../differential-testing/)
adds the rule or asks the user. It is the only mechanism in §2 that can extend an incomplete
rule set; GameGen's recall of 1.0 against raters who share its blind spots is why one is needed.

### Keeping same-author checks honest

The agent writes the program *and* the checks, so it can always satisfy the interface — and
could always satisfy the checks by writing weak ones, or by exposing a `getState()` that
reports what the rules want. That is InfiniteWeb's situation: evaluators and site by the same
model, no independent oracle. Four mechanisms make same-author checks trustworthy; they, not
the bindings, are the design.

1. **Separation in time and context.** Rules are derived from the request *before any code
   exists*, in a context that never sees the implementation (WebGrader's requirement-first
   principle). The code-writer may read the rules — that is test-driven development — but
   cannot edit them.
2. **The state cannot lie.** `render = f(state)` is enforced by remount-and-compare, and the
   wiring check ties the surface to the state. Take the broken slider: `dispatch(setK, 2)`
   then `getState().k == 2` passes — but the live frame was drawn from a stale variable, so it
   differs from `render(remount(getState()))`, and the bug is caught although `getState`
   reported the right number. Where a rule can be grounded in an observable — the rendered
   peak, the displayed total — it is; state is a trusted proxy only once purity and wiring hold.
3. **Mutation admission.** A rule set is trusted only after it rejects mutants of the first
   passing candidate — [mutation-hardened checks](../mutation-hardened-checks/), WorldCoder's
   admission criterion turned into a pipeline step and the guard against weak tests. Rules
   that never fail a mutant are flagged as vacuous.
4. **Differential testing.** A second, independently generated implementation is the one
   oracle a single author cannot fake.

None of the four depends on whether the artifact is a GUI, a game or a simulation — which is
why they are the design and the binding table is not.

## 6. Why this beats each family on its own axis

| Family | Their axis | This design |
|---|---|---|
| A · hooks by fiat | coupling by ids | binds to action *names* and to role + name on the surface; coupling is measured, not assumed |
| B · live-page contracts | neutral but model-judged | L0 `dispatch` replaces the executing agent, data predicates replace the judge: zero model calls in a verdict |
| C · state interface | schema + fixed timestep; checks hidden, hand-written | adds actions, host clock/random, injection, wiring, metamorphic rules; checks written at generation time and mutation-admitted; conformance repaired, not failed |
| D · injection | reachability solved, verdict by VLM | `setState` is injection by contract; the outcome is read as data |
| E · probes | zero coupling, zero discrimination | probes become the conformance layer; request-derived rules supply discrimination |

## 7. Decisions that change the mechanism

How a port is bound on a canvas, how coarse an action is, which roles to require — those are
bindings and implementation. Only choices that alter the verifier belong here.

1. **How strict is authorship separation?** Same model in a separate context (cheap, weaker)
   or a different model family for the rule-writer (stronger, costlier)? May the repair step
   ever propose a rule change, or only flag one for the user?
2. **When is state trusted?** Which rule kinds must be grounded in `surface()` and render
   observables, and which may read `getState()` once purity and wiring have passed?
3. **Which mutation operators make admission meaningful** without being tailored to our own
   bugs — stale state, swapped handler, wrong sign, dropped redraw, off-by-one tick, missing
   reset?
4. **What does partial coverage cost?** For a wrapped library that declares 60 % of its
   state, are rules over undeclared fields UNSUPPORTED (honest, lower coverage) or
   approximated through observables?

Scope, fixed: the verifier decides *behavioral correctness*. Layout taste and aesthetics are a
different question with a different judge, kept outside the loop; the verifier's only
statement about pictures is `render = f(state)`.

## In the papers

WorldCoder-Bench supplies the state schema, the prescribed timestep and mutation-hardening;
GameGen-Verifier the `(P, a, Q)` rule shape and state injection; GameFix the virtual clock,
tolerance bands and the zero-flake gate; WebRISE the requirement-induced statechart and
SKIPPED-vs-FAIL attribution; WebGrader requirement-first planning and a fault-set verifier
benchmark; InfiniteWeb instrumentation variables, dense per-rule reward, and the same-author
cautionary tale; AutoWebWorld the FSM-as-generator idea and its unclosed conformance gap;
HTMLCure verdict-routed repair and regression-penalized acceptance; FrontendBench and
InteractScience the cost of ids by fiat; VISTA partial credit by geometry and a principled
refusal of LLM judges; I-WebGenBench the task-agnostic probe as a floor.

## Pitfalls / open questions

- A contract shifts failure from "wrong behavior" to "wrong interface"; a verifier that only
  scores conformance has moved the problem. The harness must repair conformance.
- Rules written from an ambiguous request are ambiguous rules; differential testing exposes
  the gap but cannot resolve it without the user.
- Metamorphic relations can be vacuously true (a plot that ignores `k` satisfies "doubling `k`
  doubles the peak" when the peak is 0). Mutation admission is the guard.
- Deterministic replay hides timing bugs that only wall-clock scheduling produces; a scope
  limit to report, not a solved problem.
