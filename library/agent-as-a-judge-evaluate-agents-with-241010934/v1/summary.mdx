<TLDR>An LLM-agent judge that gathers its own evidence (project graph, file location, multimodal reading, trajectory retrieval) and then emits per-requirement `<SATISFIED>`/`<UNSATISFIED>` verdicts on developer-agent runs, introduced together with DevAI (55 AI-development tasks, 365 DAG-linked requirements); it agrees with a human-consensus reference about 90% of the time — vs 60–70% for plain LLM-as-a-Judge — at roughly 2% of the human evaluation cost.</TLDR>

<WhyItMatters>This is THE explicit contrast class for TDE. It shares TDE's premise — outcome-only grading is too sparse, so score whole agentic runs against graded, requirement-level milestones (a DAG over the final workspace) — but every adjudication is <b>model-judged</b>: an LLM agent reads artifacts and opines, correctness is defined as alignment with (noisy, 10–30%-disagreeing) human opinion, and nothing in the stack ever executes an acceptance check. TDE de-circularizes exactly this step by making the environment compute the verdict mechanically. Two sharpenings vs the survey line: the evaluation here is post-hoc scoring, not runtime gating (self-improvement use is an outlook only), and trajectory access is optional — black-box final-workspace judging (90.44% on OpenHands) matches gray-box trajectory judging (90.16%), which is itself indirect evidence that final-world-state checking carries most of the signal, as TDE assumes.</WhyItMatters>

## Motivation
<Problem>Agentic systems act step-by-step, but their evaluations are end-only</Problem>: SWE-Bench-style final resolve rates say nothing about where in a long trajectory a system failed, and a proper process-level evaluation by humans is prohibitively expensive (86.5 expert-hours for one pass over three systems here). Existing code benchmarks compound this: <Problem>HumanEval/MBPP are self-contained toy problems, SWE-Bench covers only repair, is partly solvable without agents (over 27%, citing Agentless), and invites Goodhart-style per-task mechanisms</Problem> (§1, §2.1). No benchmark reflects a full development cycle with intermediate reward signals.

## Contribution (what's new)
<Novelty>Give the judge itself agentic evidence-gathering capabilities</Novelty>: build a graph of the generated workspace, locate the files a requirement refers to, read 33 file formats (code, images, video, docs), optionally retrieve from the developer's trajectory, and only then ask an LLM for a per-requirement binary verdict. The form is forced by the baseline's failure mode: plain LLM-as-a-Judge fails at evidence selection, not judging — the ablation ladder (65.03% with `ask` alone → 90.44% with `graph`+`read`+`locate`) shows the delta is almost entirely evidence collection. Second delta: <Novelty>DevAI, a benchmark whose unit of evaluation is the requirement, not the task</Novelty> — 55 realistic AI-development queries with 365 explicit, binary requirements arranged as dependency DAGs (scored independently (I) or prerequisite-gated (D)) plus 125 softer preferences, yielding graded rather than sparse feedback. Third: a <Novelty>quantified Human-as-a-Judge study</Novelty> showing individual expert judgments are themselves unreliable, motivating the consensus-after-debate reference.

## Research questions
Can an agentic judge reproduce human-consensus requirement verdicts on full development runs at LLM cost? Which judge capabilities matter? And how far are current developer agents from completing realistic AI-development tasks?

## Methodology
Run three popular open-source "AI developers" — MetaGPT, GPT-Pilot, OpenHands (each with gpt-4o-2024-05-13 backend, visible 1800 s hard limit) — on all 55 DevAI tasks, capturing workspaces and instrumented trajectories. Three expert humans score every requirement independently (58 h), then debate to consensus (28.5 person-hours); the consensus is the reference. Judges are compared by <Term def="percentage of the 365 requirement verdicts identical to the human consensus">alignment rate</Term>, <Term def="absolute deviation of a judge's aggregate scores from the Human-as-a-Judge consensus numbers">judge shift</Term>, and PR curves, in a <Term def="judge sees only the final generated workspace">black-box</Term> and a <Term def="judge additionally gets carefully hand-collected execution trajectories — nearly inaccessible in practice (App. J)">gray-box</Term> setting.

## Main result
Across all six judge/system pairs, the agentic judge beats LLM-as-a-Judge, and on OpenHands it exceeds the best individual human: <Finding src="Tab.3, p.9">black-box Agent-as-a-Judge reaches 90.44% alignment on OpenHands vs 60.38% for LLM-as-a-Judge, above the best single human (89.89%) and the individual-human average (85.70%), though below the human majority vote (94.26%)</Finding>. Judge shift falls as low as <Finding src="Tab.3, §4.2">0.27% on Requirements-Met (I) for OpenHands, where LLM-as-a-Judge deviates by 31.42%</Finding>.

## Key findings
- <Finding src="Tab.4, App.K">Evidence selection, not judging ability, is the bottleneck</Finding>: alignment climbs 65.03% → 90.44% purely by adding evidence-gathering modules — and extra machinery (search, planning, memory) *lowers* it (86.06/88.52/87.97%), because the verdict LLM is noise-sensitive and memory chains earlier judgment errors into later ones.
- <Finding src="Tab.3, Tab.4">Trajectory access is nearly moot</Finding>: black-box (workspace-only) 90.44% vs gray-box 90.16% on OpenHands; retrieve helps only where trajectories are long and informative (GPT-Pilot 83.88% → 86.61%). Most of the judgeable signal lives in the final workspace state.
- <Finding src="Fig.4, Fig.5">The human reference itself is noisy</Finding>: pairwise expert disagreement runs 10–30%; one evaluator (cn9o) erred on 23.77% of GPT-Pilot verdicts; majority voting cuts residual error to 6.01% vs consensus. "Ground truth" here is negotiated opinion, not measurement.
- <Finding src="Tab.2">Developer agents are far from solving DevAI</Finding>: best systems satisfy ~29% of requirements when prerequisites count (GPT-Pilot 28.96%, OpenHands 28.68%; MetaGPT 6.55%) and fully solve at most 1 of 55 tasks (1.81%); MetaGPT self-terminates on only 41.81% of tasks, OpenHands on 54.54%.
- <Finding src="§4.2, Fig.7">Alignment rate is inflated by class imbalance</Finding>: since requirements are rarely met, an always-negative judge scores high — LLM-as-a-Judge hits 84.15% on MetaGPT black-box this way; PR curves (shown only for MetaGPT) are needed, where Agent-as-a-Judge tracks the majority vote most closely.
- <Finding src="§4.4">The ~97.7% cost cut comes from replacing humans, the accuracy from agentic evidence</Finding>: LLM-as-a-Judge costs almost the same in API fees ($29.63 vs $30.58) yet is 20–30 alignment points worse in the practical black-box setting.

## Implications
The paper names and legitimizes the model-judged branch of agent evaluation: requirement-level graded scoring with an LLM-agent adjudicator, extending <Related>LLM-as-a-Judge (Zheng et al. 2024)</Related> and multi-LLM judge variants (<Related>ChatEval, Auto Arena</Related>), and positioning DevAI against final-score AI-dev benchmarks (<Related>MLAgentBench, ML-Bench, MLE-Bench, SUPER, DS-bench</Related>). Its outlooks push the judge from evaluator to training signal — a process-supervised reward model and a self-play "flywheel" (<Related>Lightman et al. 2023; Pan et al. 2024, autonomous evaluation of digital agents</Related>) — which raises the stakes on judge error. A contemporaneous <Related>Cognition blog on evaluating coding agents (3 weeks before submission)</Related> is cited as convergent industry evidence. <FollowUp>How many of DevAI's 365 requirements (file exists at path, artifact saved, metric written) could be verified by executable predicates instead of a judge — the missing mechanical-checker baseline TDE would supply.</FollowUp> <FollowUp>Robustness of judge agents to adversarial artifacts/prompt injection — the LLM-judge robustness literature is cited (Raina et al.) but never tested.</FollowUp>

## Limitations
- <Caveat>Every verdict is an LLM opinion about natural-language criteria; the judge reads artifacts but never executes them</Caveat> — and neither did most humans (231a: "No need to run the code"; cn9o "did not execute anything"), so no layer of the stack is grounded in mechanical verification.
- <Caveat>Correctness is defined as alignment with a human consensus whose own error is acknowledged but unquantified</Caveat>; with 8–14% residual misalignment, per-requirement reward signals would be systematically wrong for self-improvement use.
- <Caveat>Proof-of-concept scope (authors' framing)</Caveat>: single unnamed judge backend, no prompt/workflow optimization, single run without variance, one domain (small-scale AI development, workspaces of hundreds of LOC — which is why search was moot), 55 tasks.
- <Caveat>The "better than an individual human" claim holds only partially</Caveat>: in black-box, MetaGPT (88.52% vs 89.34% individual average) and GPT-Pilot (83.88% vs 84.88%) fall below the average lone human; the claim rests mainly on OpenHands and gray-box numbers.
- <Caveat>125 preferences are collected but no preference-satisfaction results are reported</Caveat>; gray-box trajectories are "nearly inaccessible in practical situations" by the authors' own note; minor internal inconsistencies (92.07% prose vs 90.16% table; 31.24% vs 31.42%; §4.4 swaps the cost/time percentages relative to the intro).

## Critiques and Questions
1. Circularity: the judge is validated against negotiated human opinion, and the outlook is to use the judge as a reward model for agents — a model judging a model, calibrated on humans who didn't run the code. Nothing anywhere computes ground truth from the environment. This is precisely the adjudication loop TDE proposes to break with environment-evaluated postconditions.
2. DevAI's requirements were deliberately authored to be "explicit, binary, and straightforward to evaluate" (App. E.2) — i.e., largely mechanically checkable (paths, saved artifacts, file contents). The natural baseline — a scripted verifier over the checkable subset — is absent, so we cannot tell how much of the 90% alignment an LLM-free checker would already achieve. Conversely, the genuinely judgment-requiring criteria (the preferences) are never evaluated, so the framework is untested exactly where model judging would be irreplaceable.
3. The black-box ≈ gray-box result undercuts the paper's own "step-by-step evaluation" framing: the intermediate feedback is milestone-level over final state, not per-action process supervision, and it is post-hoc — no runtime gating of actions exists here.
4. Alignment is per-requirement but judge shift is aggregate, and PR curves are shown for MetaGPT only; the OpenHands PR claim has no visible figure. Compensating errors could hide in the aggregate metrics.

### Personal notes
For the TDE novelty defense, the load-bearing characterization: Agent-as-a-Judge is post-hoc, model-adjudicated, requirement-level scoring calibrated to human opinion — no execution, no runtime gating, no environment-computed predicate anywhere. Its best pro-TDE datum is accidental: black-box (final-workspace) judging ties gray-box (trajectory) judging, supporting final-world-state verification as the right locus. Its best anti-TDE argument is coverage: an LLM judge can grade any NL requirement (though the paper never tests the subjective ones). Cite the App. E.2 line that requirements were authored "explicit, binary, straightforward to evaluate" — that is exactly the compilable-to-tests regime TDE targets, minus the compiler.
