<TLDR>COBA audits agent benchmarks by mapping every task into a standardized four-component representation — User, Environment, Ground Truth, Evaluation — then running deterministic structural rules plus a taxonomy-conditioned LLM judge (with an optional rebuttal agent) and human-verifying every flag; it validates flaws in 4.3–66.7% of tasks across eight tool-use benchmarks and shows that filtering them reorders 18 of 30 ACEBench model ranks.</TLDR>

<WhyItMatters>The most directly relevant paper of my ICML 2026 batch: benchmark auditing is my core evaluation-methodology lane, and this gives me a component vocabulary, an 11-category flaw taxonomy, and a two-protocol human-validation design to reuse — plus a quantified answer to the question my reliability thread ("Towards a Science of AI Agent Reliability", "Implicit Intelligence") keeps raising: how much of an agent leaderboard is measurement error.</WhyItMatters>

## Motivation
<Problem>Agent benchmarks contain hidden validity flaws that confound model errors with benchmark artifacts and undermine leaderboard comparisons</Problem> — e.g. about 38% of τ-Bench tasks pass if the database is left unchanged (a "do-nothing" exploit, figure cited from Zhu et al. 2026), and ground-truth trajectories violate their own tool schemas or policies (§2.2). <Problem>Prior benchmark-quality work (label-error audits, "platinum" curation, unit-test augmentation) targets static, single-component datasets; agent-benchmark flaws instead arise from *interactions* among user simulation, tools, environment state, reference trajectories, and evaluation protocols, where manual inspection does not scale</Problem> (§1, App.A) — the manual verification of τ²-bench (Cuadron et al. 2025) is effective but expert-labor-bound.

## Contribution (what's new)
<Novelty>A standardized task representation T = ⟨User, Environment, Ground Truth, Evaluation⟩ that makes heterogeneous agent benchmarks auditable by one pipeline — the only benchmark-specific code is a data-loading mapping into T</Novelty> (§3.1). On top of it, <Novelty>an 11-category, component-aligned issue taxonomy distilled bottom-up by five annotators from 21–29% samples of six benchmarks</Novelty> (§2.2, Tab.2), and <Novelty>a hybrid detector: deterministic rules for structural violations, a taxonomy-conditioned LLM judge for semantic ones, and an optional adversarial rebuttal agent that re-reviews flags under explicit adjudication principles</Novelty> (§3.2–3.4). The design is forced by the baseline's failure mode: an unstructured critique prompt over-flags 1.7x and loses ~73% of disagreements to the taxonomy prompt (§4.4) — structure, not the LLM, is what makes the judge reliable.

## Research questions
1. Can agent-benchmark validity failures be organized component-wise into a reusable taxonomy? 2. Can an automated pipeline reproduce expert issue judgments at scale and transfer to unseen benchmarks? 3. Do benchmark flaws materially change model scores and leaderboard order?

## Methodology
Each task is mapped into T; <Term def="rule-based detectors for explicit violations (schema breaks, role confusion in dialogue logs) — precision-first, correct by construction, excluded from the human-alignment evaluation">Stage 1</Term> removes deterministic violations, then <Term def="an LLM judge (default Gemini-2.5-Pro-Thinking) conditioned on the full task T plus the 11-category taxonomy, emitting (flawed?, category, rationale) in a fixed JSON schema">Stage 2</Term> reasons about semantic/contextual flaws. An optional rebuttal agent re-reviews flagged tasks and may overturn them. Every pipeline flag is then human-verified. The taxonomy (Tab.2, p.3): **User** — ambiguous instruction; <Term def="the LLM user simulator behaves like the assistant, e.g. announcing 'your reservation has been canceled'">user role confusion</Term>. **Environment** — incorrect tool-call responses; insufficient toolset; misleading tool design; incorrect system prompt. **Evaluation** — too lenient; too strict. **Ground Truth** — malformed tool calls; incorrect tool calls; redundant/ungrounded tool calls.

## Main result
**Pipeline validity.** <Finding src="Tab.3, p.6">The taxonomy-guided judge reaches F1 0.791–0.874 against expert labels on the five seed benchmarks with a semantic stage (DrafterBench is rules-only, so it has no F1) — precision 0.846–0.878, recall 0.720–0.882 (recall exceeds precision only on ACEBench)</Finding>; at full-benchmark scale, 72.1–92.0% of flags survive expert post-hoc verification (the "Val. Acc" column — the share of flagged tasks experts confirm), and validated issue rates run 11.8–24.2% on the seed benchmarks (DrafterBench: 66.7%, dominated by deterministic duplicates).

**Does filtering change evaluation outcomes? Yes — scores and order.** On ACEBench (the one benchmark analyzed for this), <Finding src="Tab.6+Tab.11, p.8/20">removing the 121 validated issues raises every one of 30 models' scores (+1.9 to +5.3 points) and shifts 18/30 ranks — the intro's "60% of rankings altered" — while the top two (gpt-4o-20240806, gpt-4.1) hold</Finding>. <Finding src="§4.6, p.8">The reordering is systematic, not removal noise: cleaned-vs-original Kendall's τ is 0.871 vs 0.960 for random removal of the same task count over 100 trials (95% CI 0.935–0.981), pairwise flip rate 5.75% vs 1.50% (95% CI 0.46–2.65)</Finding> — though each model was evaluated in a single run.

## Key findings
- <Finding src="Fig.5, p.8">Flaws do not bias in one direction — they add variance</Finding>: grouping ACEBench tasks by dominant issue effect, inflation-prone tasks average 1.000, unsolvable 0.035, deflation 0.555, noise 0.666, vs 0.780 on the cleaned benchmark; the competing effects net out to every model's score *rising* after filtering.
- <Finding src="§4.2.2, p.6">COBA complements — and partially subsumes — τ²-bench's manual verification</Finding>: on Airline+Retail it recovers 11 of 15 manually identified *objective* issues (scope excludes clarity/ambiguity/presentation), adds 14 validated in-scope issues the manual pass missed, and surfaces whole issue types outside its scope: role confusion prevalent in Telecom's <Term def="τ²-bench setting where both agent and user can act on the environment">dual-control</Term> tasks and do-nothing evaluation loopholes in Airline/Retail.
- <Finding src="Tab.4, p.7">"Minimal adaptation" to unseen benchmarks means exactly one loader</Finding>: for BFCL V4 and NexusBench (untouched during taxonomy/pipeline development), the authors wrote only the field-extraction mapping into T and reused prompts and detection logic unmodified — F1 0.842 and 0.811, with 11 and 141 validated issues. But at-scale flag precision on BFCL V4 is only 57.9%.
- <Finding src="Tab.5, p.7">The taxonomy is load-bearing</Finding>: a generic critique prompt flags 1.7x more tasks, and in the 114 (ACEBench) and 202 (CFB) disagreement cases the taxonomy prompt wins 72.8% and 73.3% of manual adjudications.
- <Finding src="Fig.4, p.7">Ground-truth issues dominate most benchmarks; the τ-family is the exception</Finding>, with large User-simulation and Evaluation shares (τ-Bench: User 21.0%, Env 30.6%, Eval 22.6%, GT 25.8%, Tab.1) — the empirical justification for auditing all four components. In CFB, COBA validated up to 126 previously unreported issues.
- <Finding src="Tab.9+Tab.10, p.19">Judge choice trades precision for recall, and residual errors are structured</Finding>: avg precision/recall is 0.862/0.787 (Gemini-2.5-Pro-Thinking), 0.861/0.624 (Claude-4-Opus-Thinking), 0.748/0.846 (DeepSeek-V3.1-Thinking); the rebuttal stage lifts precision 0.865→0.918 (ACEBench) and 0.878→0.910 (CFB) at a "moderate" recall cost (values Not reported). False negatives are dominated by malformed tool calls (46.8%) — ironically the most rule-detectable category — and false positives by partial-trajectory over-strictness (17.7%).

## Implications
This moves agent-benchmark quality from anecdote (scattered bug reports, one-off manual revisions) to an auditable, component-level protocol — the agent-benchmark analogue of <Related>Northcutt et al.'s label-error audits</Related> and <Related>Vendrow et al.'s platinum benchmarks</Related>, and the audit-time complement to <Related>the design-time ABC checklist (Zhu et al. 2026)</Related> and <Related>domain-specific validators like UTBoost for SWE-bench</Related>. The concrete deliverable is AgentSuite: a unified runner packaging the COBA module, plus filtered variants and manually repaired ("fixed") artifacts guided by COBA's reasoning traces — repair recovers much of the coverage filtering costs (mean category retention 0.33–0.85 after filtering across the six seed benchmarks, 0.81–1.00 after fixes; fixable share 20–100%, Tab.8). <FollowUp>Whether leaderboards actually adopt audited variants — or the variants just fork benchmark truth</FollowUp>; <FollowUp>whether T = ⟨U, E, G, V⟩ maps onto outcome-graded benchmarks without reference trajectories (WebArena-style web/OS agents, SWE-bench)</FollowUp>; <FollowUp>hardening rules for the malformed-call false-negative hotspot</FollowUp>; <FollowUp>Cuadron et al. 2025 (SABER), the manual τ²-bench verification this paper measures itself against</FollowUp>.

## Limitations
- <Caveat>Author-stated: the taxonomy is not exhaustive; the pipeline inherits LLM-judge biases; cleaned/repaired artifacts are "maintained artifacts", not a guarantee remaining tasks are flawless</Caveat> (§5).
- <Caveat>Judge circularity: the default auditor is Gemini-2.5-Pro-Thinking, and Gemini-2.5-pro-thinking-on gains 5 ranks (14→9) on the cleaned leaderboard its own judgments produced</Caveat>; human verification covers *flagged* tasks only, so false negatives at scale are unmeasured beyond the small balanced subsets.
- <Caveat>Expert labels are five graduate researchers (relationship to the author list Not reported); the dominant disagreement — acceptable ambiguity vs underspecification — is exactly the boundary the "Ambiguous instruction" and "Too strict" categories must draw</Caveat>, so filtered variants encode the annotators' judgment calls, κ 0.824 notwithstanding.
- <Caveat>Coverage: all eight audited benchmarks are tool-use/function-calling or customer-support dialogue; no web, GUI/OS, or coding-agent benchmarks, and the representation presumes a reference trajectory G</Caveat> — generality beyond this family is untested.
- <Caveat>The ranking-impact result is one benchmark (ACEBench), single evaluation run per model; leaderboard effects on the other seven benchmarks are Not reported</Caveat>.
- <Caveat>F1 is measured on class-balanced subsets (50% issue prevalence); at deployment prevalence (4–24%) the honest number is at-scale flag precision — 72.1–92.0% on seed benchmarks but 57.9% on unseen BFCL V4</Caveat>, i.e. over-flagging grows where the pipeline is newest.
- <Caveat>Filtering shrinks capability coverage unevenly: mean category retention drops to 0.67 (τ-Bench), 0.70 (τ²-bench), 0.33 (DrafterBench)</Caveat>; the repair path that restores it is manual.

## Critiques and Questions
1. **Circularity, sharpened.** An LLM judges the benchmarks that rank LLMs — including its own family, which rises after cleaning. The judge-swap ablation shows recall varies widely by judge (0.624–0.846), so a Claude- or DeepSeek-audited "clean" set would differ at the margin. How judge-flavored is the 18/30 reordering? Rerunning Table 6 with issue sets from each judge would answer it; the paper doesn't.
2. **Internal vs construct validity.** COBA audits task-level correctness, not what the benchmark measures. The *cleaned* ACEBench still ranks gpt-4o-20240806 first and gpt-5 27th, and claude-4.5-sonnet lands 3rd with thinking-on vs 29th with thinking-off — harness/configuration sensitivity that filtering cannot touch. "Cleaned" should not be read as "valid".
3. **Bookkeeping discrepancies worth checking before adopting the artifacts.** §2.2 says the six seed benchmarks total 5,086 tasks, but Table 3's denominators sum to 5,186. And the GitHub release (v1 repo read) removes fewer tasks than the paper validates as flawed — e.g. τ²-bench: 41 removed in the repo's filtered variant vs 67 validated here; CFB: 129 vs 162. Which issue set ships is Unclear.
4. **The impact taxonomy is under-specified.** How a task gets assigned a *dominant* impact category (inflation/deflation/unsolvable/noise) for Fig.5 is not described; and the headline "27% average" leans on DrafterBench's 66.7% duplicate-driven rate — excluding it, the seed-benchmark mean is ~18.5%.
5. **Is the rebuttal on or off in the shipped variants?** It changes precision/recall materially (0.865→0.918 with recall loss unreported), but whether released filtered sets used it is Not reported.

## Glossary
