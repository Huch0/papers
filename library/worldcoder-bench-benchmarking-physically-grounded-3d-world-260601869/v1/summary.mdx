## Motivation
When a model writes a web page, you can at least read the DOM. When it writes a Three.js world, everything that matters — positions, velocities, collision flags, the phase of a game — lives inside a JavaScript runtime and is painted into one opaque `<canvas>`. <Problem>Screenshots, DOM walkers, and even an external agent all observe the world from the outside, so "looks right" stops being a proxy for "works right": a ball can pass through the hoop on screen while the score never increments.</Problem> Prior web-generation benchmarks under-test exactly the three things a world needs: physical correctness, asset integration, and state synchronization between engine and HUD (Fig.2). We measured the cost of that blind spot before building anything else: <Problem>DOM-based scoring has a per-pair Kendall τb of −0.02 with hidden state-level correctness, and an 8-turn inspection agent still grants passing marks to 45.6% of severely defective outputs</Problem> (§1, Tab.2).

## Contribution (what's new)
The mechanism that survives deleting "we propose": <Novelty>make the program's own state observable by requiring a small runtime interface (`window.__3D_STATE__` with task-specified fields), then verify behavior by scripting actions and asserting on before/after state deltas against a contract the model never sees</Novelty> (§3.3). This is forced by the canvas: there is no other channel to read velocities or phases from. The second mechanism is what keeps the checks honest: <Novelty>every contract is admitted only after it rejects a battery of injected defects — stale state updates, scaled physical constants, broken asset loading, swapped event targets, HUD mismatches — so a pass reflects behavior, not slack thresholds</Novelty> (§3.2). Around that we built the benchmark itself (three macro-categories, 15 domains, difficulty D1–D6, asset tiers), a robustness split with rewritten contracts under randomized constants, and two utility metrics — <Term def="quality-adjusted dollars of developer labor replaced per dollar of API cost">Return on Automation</Term> and <Term def="quality-adjusted human hours saved per hour of model generation">Time Efficiency Multiplier</Term> — that discount cheap-but-wrong outputs (Eq.1).

## Research questions
Can frontier models synthesize behaviorally correct 3D worlds from a brief? Do external evaluators reproduce a state-level ranking? Where exactly do generated worlds fail? And what is a partially correct world worth in labor terms?

## Methodology
A task is a directory `(task.json, assets/)`; the model returns one self-contained HTML file. StateProbe loads it in headless Chromium via Playwright with a version-locked Three.js, checks executability (a live WebGL context, a render loop, no early exceptions → otherwise `RUNTIME_CRASH`), then runs deterministic action probes — clicks, key presses, drags, physics-step commands — snapshotting state before and after each and checking the hidden assertions (§3.3). Coverage is reported at four levels: Affordance (expected objects and controls exist), State (required states reachable), Transition (action-triggered postconditions hold), and Verification (share of all hidden assertions passing, the leaderboard metric) (§3.4).

## Key findings
- <Finding src="Tab.2">External judges do not work here: DOM-only inspection has τb −0.021 with V-Cov and a 33.7% false-pass rate at unit cost; screenshot+VLM (GPT-5.4) has τb −0.068 at ~50× cost; an 8-step inspection agent is the only one with positive correlation (+0.111) but passes 45.6% of worlds whose true coverage is below 30, at ~400× cost.</Finding> Per model, DOM scoring inverts the ranking (τb −0.238; DeepSeek-V3.2 scores 54.7 vs GPT-5.4's 50.0, Tab.13).
- <Finding src="§4.5, Tab.14">Two failure modes explain 83.6% of zero-transition records: State Schema Drift (42.8%; the exposed interface deviates from the specified schema) and Broken Interaction Chain (40.8%; handlers do not update the exposed state). Physics violations are rare (0.4%); models understand the intent.</Finding>
- <Finding src="Tab.3">Perturbing constants, counts, and asset names (Robust split) drops GPT-5.4 to 19.9% and Qwen3.6-Plus from 25.3% to 13.5% — a signature of template recall over mechanism understanding — and widens the proprietary–open gap from 2.5 to 6 points.</Finding>
- <Finding src="Tab.12">Rendering is easiest (materials, shaders, post-processing lean on idiomatic Three.js APIs; shaders up to 60.5% for Gemini) and Application hardest (game 5.0–12.8%); the creative domain scores 0.0% for every model.</Finding>
- <Finding src="Tab.11">System-level failures differ more than behavioral ones: DeepSeek-V4-Flash crashes on 42.4% of tasks; Kimi-K2.5 omits the required state object on 10.2%; per-task tokens range 5,418–15,843.</Finding>
- <Finding src="Tab.1, Fig.6">Utility inverts capability: DeepSeek-V4-Flash tops RoA at $19,150 of labor per API dollar (30× any proprietary model) while GPT-5.4 wins TEM at 68.9× by pairing the highest coverage with the lowest latency (88 s/task); value concentrates in materials, shaders, and post-processing.</Finding>

## Implications
The paper is convergent evidence that, for interactive programs, the checker must read state from inside the program — and that once it does, screenshot, DOM, and agent judges are not merely noisy but rank-inverting. <Related>It generalizes the requirement-side contracts of WebRISE (interaction graphs judged by an agent) into program-side state contracts, and shares its mutation-testing calibration with WebRISE's defect injection and GameGen-Verifier's state injection.</Related> <FollowUp>WorldCoder-Dev's 200 public tasks with released contracts are a second programmatic ground truth; the dominant "schema drift" failure is an argument for one small, fixed contract rather than per-task schemas; and their probes have no action API of the program's own — actions are DOM events and key presses — which is exactly the gap a dispatch-by-name contract fills.</FollowUp>

## Limitations
<Caveat>Hidden contracts mean Core/Extended/Robust results cannot be independently re-verified; only the Dev split is public, and the repository is anonymous at preprint time.</Caveat> <Caveat>"State Schema Drift" conflates interface non-compliance with behavioral error: a world can be correct yet fail because its exposed field names differ, so V-Cov is partly a measure of instruction following.</Caveat> <Caveat>Human-effort estimates behind RoA/TEM rest on seven expert-annotated tasks plus a difficulty fallback (App.C.1); failure modes are classified by an LLM grader (App.D.1); external-paradigm comparisons cover seven of nine models.</Caveat>

## Critiques and Questions
1. No human agreement is reported for the contracts themselves — mutation-hardening guards against slack contracts, not against over-strict ones; a correct-but-different world could still fail an assertion written against one reference behavior.
2. Since drift and chain failures dominate, a repair loop that reads the contract failure (which the model never sees here) would likely lift coverage substantially; the benchmark measures single-shot generation only.
3. Cost is normalized to DOM inspection (~2× for StateProbe) without absolute numbers, and the ~400× agent figure depends on the agent's turn budget.
