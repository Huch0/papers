Curated byChiyeong Heo

Repairs buggy student C programs by wrapping zero-shot ~7B open LLMs in a CEGIS loop — MaxSAT-based fault localization deletes the minimal set of suspect statements to form a bug-free sketch, the LLM fills the holes, and a Decider executes the candidate against the assignment’s IO test suite, feeding one failing test back as a counterexample — repairing more programs with smaller patches than symbolic APR tools for all six LLMs evaluated.

The archetypal CEGIS-shaped TDE relative (survey cat. G): synthesize → mechanically verify → concrete failing test as feedback, with the LLM excluded from adjudication (the Decider is plain test execution) and even the LLM’s writable region fixed mechanically by MaxSAT fault localization. It differs precisely where TDE lives: the oracle is a pre-existing, lecturer-authored IO test suite for a fixed assignment — nothing is compiled from the NL instruction at runtime — it verifies program text, not final environment state in an agent loop, and there is no per-action pre/postcondition gating. Also a sharp data point for SWE-agent harness design: mechanical verification plus concrete counterexamples lets 4-bit 3.8–8B models beat specialized symbolic tools.

Motivation

Programming courses enroll thousands of students, and personalized feedback on IPAs costs faculty substantial time. Symbolic FM-based repair tools (CLARA, Verifix) produce high-quality fixes but are slow and require the buggy program and a correct implementation to share the same control-flow graph — otherwise they return a structural mismatch error; within the paper’s 90 s budget CLARA repairs only 495/1431 programs (34.6%) and Verifix 91 (6.3%) (p.5–6). LLMs are fast but rewrite extensively instead of minimally, and when a reference implementation appears in the prompt they copy it outright, ignoring instructions not to (p.2–3) — invasive patches students cannot learn from. In the motivating max-of-three example, neither CLARA, Verifix, nor basic-prompted Granite/CodeGemma can fix a 12-line, two-bug program within 90 s (p.2–3).

Contribution (what’s new)

A division of labor in which formula-based fault localization decides where the fix may go, a zero-shot LLM decides what text goes there, and test execution decides whether it worked — repair becomes constrained string completion. The MaxSAT-localized minimal diagnosis is deleted outright, so the LLM sees a bug-free sketch whose @ HOLE N @ placeholders bound the patch surface by construction, attacking both baseline failures at once (symbolic CFG-brittleness; LLM over-editing and copying). A CEGIS loop closes the system: each failed candidate triggers a feedback prompt carrying one concrete failing IO test as a counterexample. In the motivating example, the two-hole sketch lets Granite and CodeGemma repair in a single interaction a program neither could fix from a basic prompt (p.2–3). Claimed as the first LLM-repair work guided by formula-based fault localization (p.8).

Research questions

RQ1: Do SOTA LLMs repair IPAs better than semantic repair tools? RQ2: Which prompt configurations matter? RQ3: Does FM-based fault localization improve LLM-driven APR? RQ4: Does providing a reference implementation help? RQ5: What does counterexample guidance add? (p.4)

Methodology

A four-module pipeline (Fig.1, p.3): CFaults marks the minimal set of buggy statements; a prompt generator builds one of three prompt families — basic (raw buggy program), FIXME-annotated, or hole-sketch — optionally adding the assignment description, test suite, a correct program, and the counterexample loop; the LLM synthesizes a candidate; the Decider executes it on the IO test suite and on failure returns one failing test. Evaluated on C-Pack-IPAs with six open instruction-tuned LLMs (Granite 8B, CodeGemma 7B, CodeLlama 7B, Gemma 7B, Llama3 8B, Phi3-mini 3.8B), 4-bit quantized on one 16 GB GPU, 90 s / 10 GB per repair. Metrics: programs repaired, plus a patch-quality distance score built on TED that penalizes larger-than-necessary patches (Eq.1, p.5).

Method details
  1. Localize (MaxSAT FL) — CFaults encodes the program plus all failing test cases into a unified MaxSAT formula (model-based diagnosis) and enumerates minimal diagnoses — the smallest statement sets explaining every failing test. The FL module is explicitly pluggable.
  2. Sketch + prompt — Each diagnosed statement is replaced by `@ HOLE N @`, yielding a bug-free program sketch (Listing 3). The prompt = command ('Complete all the @ HOLES N @ in the incomplete program below'), IPA description (De), IO test suite (TS), optionally a correct program — lecturer reference (RI) or the AST-closest prior correct student submission (CPA) — and the sketch. Alternatives: basic prompt ('Fix all semantic bugs... Modify the code as little as possible') or FIXME-annotated prompt marking each localized line.
  3. Synthesize (zero-shot LLM) — An off-the-shelf instruction-tuned model completes the holes: Granite 8B, CodeGemma 7B, CodeLlama 7B, Gemma 7B, Llama3 8B, Phi3-mini 3.8B (128K context). All 4-bit quantized to fit a 16 GB RTX A4000, run via HuggingFace Pipeline; no fine-tuning, no in-context examples.
  4. Decide + feedback (CE) — The Decider runs the candidate on the full test suite (repair tasks on a Xeon Silver 4210R, 10 GB memory, 90 s timeout). On failure, a feedback message — 'Your previous suggestion was incorrect! Try again. Code only.' — plus one failing test's input and expected output is appended, and the LLM re-synthesizes. Among successful repairs: min 1, mean 1.14, max 7 iterations.

The score is 0 when the patch is as far from the original as wholesale replacement by the reference (i.e. copying), and approaches 1 for minimal edits; Table 3 reports its sum over each configuration’s successfully repaired programs. Baselines: CLARA (needs a cluster of correct submissions) repairs 495, times out on 154 (10.8%); Verifix (needs the lecturer reference) repairs 91, fails on 93.5% — both demand an exact control-flow-graph match and a variable bijection.

Main result

Bug-free sketches improve all six LLMs over the same prompt without localization; the best no-reference configuration, Granite + Sk De-TS, repairs 691/1431 (48.3%), vs CLARA 34.6% and Verifix 6.3% (Tab.2, p.6). An all-LLM portfolio with sketches + counterexamples repairs 907 (63.4%), and 1,013 (70.8%) over all no-reference configurations; adding reference implementations pushes it to 1,190 (83.2%) — but largely via copying (see Key findings). Key findings

  • Sketches are the load-bearing component: vs the basic prompt they add +85 (CodeGemma), +81 (CodeLlama), +65 (Granite), +53 (Phi3), +36 (Gemma) repairs — but only +14 for Llama3 (Tab.2, p.6): the FL signal pays off most for the code-specialized models, and the strongest general model is nearly indifferent to it.
  • FIXME annotations — the same FL information as comments instead of holes — reduce repairs for every LLM in the no-reference setting (Tab.2, p.6) (e.g. Granite 566 vs 626; portfolio 796 vs 842): localization only helps when it reshapes the artifact, so the paper’s RQ3 answer (“Sketches or even FIXME annotations” help) is supported by the evidence for sketches only.
  • The CEGIS loop barely iterates: mean 1.14 iterations (max 7), and 89% of successful repairs pass on the first attempt (p.7); counterexamples give consistent gains only for CodeGemma (+6 to +9) and Llama3 (+13 to +26), mixed or negative elsewhere — the title’s counterexample guidance is the smallest lever in the system.
  • Reference implementations inflate counts but corrupt patch quality: Granite reaches 876 repairs (61.2%) with Sk De-TS-CE-RI, yet 442 of them (50.5%) are verbatim copies (TED 0 to the reference), and its cumulative distance score drops from 533.6 to 334.5 (Tab.2–3 + Fig.2, p.6–7) — mean per-repair quality roughly 0.78 → 0.38 (computed from Tab.2–3).
  • On the subset CLARA structurally cannot repair (54.7% of the benchmark), Granite + Sk De-TS still fixes 290 programs (37.0%) (Tab.4, p.6) — the hybrid covers exactly the control-flow blind spot that defeats alignment-based symbolic tools.
  • Repair rate collapses with cyclomatic complexity: from 76.5% (CodeGemma, Q1: 1.0–2.5) to at best 17.1% (Granite, Q4: 7.0–26; CLARA 10.9%) (Tab.5, p.6) — every method, symbolic or neural, struggles above complexity 7.

Implications

Evidence that verifier-in-the-loop harness design substitutes for model scale: small, quantized, off-the-shelf models — chosen deliberately for classroom cost and student-data privacy — beat specialized symbolic tools once localization and adjudication are mechanical. The lineage is CEGIS and sketch-based synthesis (Solar-Lezama et al. 2005/2006; Jha et al. 2010) plus MaxSAT fault localization (Bug-Assist, Jose & Majumdar 2011; model-based diagnosis, Reiter 1987; CFaults, FM 2024); it contrasts with RING (few-shot repair using FL from error messages, AAAI 2023) and PyDex (iterative Codex querying for Python IPAs, OOPSLA 2024). The v1 PDF carries the AAAI 2025 copyright block. Whether FL-derived holes transfer to repo-scale APR (SWE-bench-style), where minimal diagnoses and full-suite execution are far costlier; held-out-test evaluation to measure how often hole fills overfit the given suite.

Limitations

  • No held-out tests: “repaired” means passing the same suite that supplies the counterexamples, so patch overfitting is unmeasured — the distance score penalizes oversized rewrites, not wrong-but-plausible hole fills.
  • Single benchmark of small C90 intro assignments, authored by the same group; generalization beyond IPAs is untested, and everything collapses above cyclomatic complexity 7.
  • No variance, seeds, or significance testing; decoding parameters (temperature, samples per query) are not reported — “significantly improves” is colloquial, not statistical.
  • The 90 s budget structurally penalizes the slow symbolic baselines (CLARA times out on 10.8%); whether FL time counts inside the budget is Unclear.
  • Only 3.8–8B open models under 4-bit quantization (a deliberate cost/privacy choice); frontier-model behavior with sketches is unknown.
  • Table 3’s distance score is a sum over repaired programs, conflating repair count with per-patch quality; per-repair means are never reported.

Critiques and Questions

  1. The RQ3 conclusion overstates FIXME annotations: without a reference implementation they reduce repairs for all six LLMs. Why annotating fails while deleting works (attention to residual buggy text? instruction-following limits?) is exactly the interesting question, and it goes unasked.
  2. Internal count inconsistency: the CLARA-fail subset is stated as “738 programs (54.7%)”, but 54.7% of 1,431 is ~782, and Table 4’s percentages are consistent with a ~782 denominator (e.g. 290/782 = 37.1%); CLARA’s outcome row (495 + 154 + 738 = 1,387) also fails to sum to 1,431. The 738 looks like a typo for 782.
  3. The text claims Granite “leads” without reference implementations at 59.1%, but Llama3’s portfolio row is higher (851, 59.5%); Granite leads per-configuration, not on portfolios.
  4. MaxSAT FL is only as sound as the test suite: with weak suites the minimal diagnosis can delete the wrong lines, and FL precision (how often holes land on the true bug) is never measured.
  5. Since 89% of repairs need one iteration, how much of the win is localization vs iteration? A budget-matched ablation (basic prompt with more CE rounds vs sketch with none) would isolate it; Sk De-TS ≈ Sk De-TS-CE in Tab.2 already hints the loop is nearly vestigial.
In this paper's CEGIS loop, what plays the verifier, and what exactly does the LLM receive when its candidate fails?
The Decider — plain execution of the candidate program against the assignment's IO test suite; no LLM judges anything. On failure, the prompt generator sends a feedback message stating the previous suggestion was incorrect, plus one concrete counterexample (a failing input with its expected output), and asks for revised code only.

Personal notes

Ingested for the TDE related-work corpus (survey cat. G). Reusable mechanics for TDE: (1) the verifier returns a concrete counterexample, not a scalar score — the red test is the feedback signal; (2) the formal component also constrains the LLM’s writable region (holes), a static cousin of TDE’s per-action gating; (3) adjudication is execution-only. Asymmetries to cite in the novelty defense: the suite is human-authored and pre-existing (no NL→suite compilation), the oracle is program IO rather than world state, there is no runtime action gating, and the CEGIS iteration is nearly vestigial here (89% one-shot) — mechanical localization, not the loop, carries the result.
