Curated byChiyeong Heo

Persona2Web benchmarks whether web agents can resolve deliberately under-specified tasks on 105 live websites by inferring implicit preferences from year-long synthetic browsing histories: without history access every agent scores 0% success, and with it the best configuration reaches only 13%.

User history is a harness-level input, and this benchmark makes it first-class for open-web navigation — scoring memory retrieval and utilization separately from navigation, exactly the attribution needed when designing context-conditioning for web/computer-use agents. It extends the Mind2Web / WebArena / WebVoyager lineage (whose site pools it literally reuses) from instruction-following to personalization; an ICML 2026 advisor-review pick.

Motivation

Real users under-specify, assuming systems know their context — yet existing web-agent benchmarks issue fully specified instructions, so they cannot distinguish an agent that understands the user from one that merely follows orders (§1). The benchmarks that do carry user context avoid the web: PersonalWAB reduces personalization to abstract function calls and Apollonion to dialogue, while no navigation benchmark (Mind2Web, WebArena, WebVoyager, WebCanvas) provides realistic user context at all (Tab.1, §2). Compounding this, outcome- and action-level scoring cannot attribute a failure to personalization vs navigation — the open web admits many valid trajectories, and both error sources collapse into the same failed outcome (§2, §3.3).

Contribution (what’s new)

The clarify-to-personalize principle: mask query slots so the only route to success runs through the user’s history — the target “level 2” query names neither the website nor the preference values (“Search for doctors in my usual area that match my preferred provider gender at my preferred website”, Tab.2). Two choices turn this into inference rather than lookup: preferences are embedded implicitly — only 3.56% of the 102,568 history entries state a preference verbatim, and one event’s actions are dispersed across a year of logs, forcing integration of remote entries (§3.1–3.2); and a reasoning-aware judge splits each personalization score into retrieval accuracy and utilization accuracy read from reasoning traces, scored separately from intent satisfaction (§3.3). Both are validated as load-bearing: making context explicit inflates success by up to +0.14 (Tab.7), and completion-only scoring conflates opposite failure modes (§5.3).

Research questions

Can current web agents resolve ambiguous tasks by inferring preferences from behavioral history? Where does the pipeline break — recognizing that history is needed, retrieving the right entries, or applying them during navigation? And can a rubric-based LLM judge measure personalization separately from navigation, reliably enough for a live-web benchmark?

Methodology

The user side is fully synthetic. GPT-4o generates 50 demographically balanced profiles, expands each into recurring event seeds, decomposes events into timestamped actions, and renders ~2,051 history entries per user over one year — each a structured record (timestamp; one of five action types: web search, web visit, purchase, booking, review & rating; an object description; a website) spanning on average 35 of the 105 live sites (§3.1, App.A). Each of 50 tasks ships three query variants of increasing ambiguity (150 queries); level 2 masks both website and preferences and is the evaluation target (Tab.2). The evaluated agents are AgentOccam and Browser-Use, each wrapped in the authors’ planner–retriever–generator personalization module and run with no-history, on-demand, or pre-execution access (§4). GPT-5-mini judges the full trajectory against rubrics; success requires perfect personalization and intent scores (§3.3).

Construction, rubrics, and judge validation
  1. Profiles and domains (§3.1, App.A.1) — GPT-4o constructs 50 profiles with evenly distributed demographics (occupations across six sectors), selects relevant domains per user from 21 predefined domains with rationales, and writes per-domain preferences plus recurring behavioral patterns. The site pool starts from 144 websites used in Mind2Web, WebArena, and WebVoyager, filtered for CAPTCHAs, geo-restrictions, and staleness down to 105.
  2. Events → actions → history (§3.1) — Event seeds define recurring activity patterns (high-frequency routines vs low-frequency irregular events); about 10% of records receive cancellations or modifications as realism noise. Each event decomposes into timestamped actions of the five types, deliberately dispersed across the year so recognizing a pattern requires integrating remote entries. Totals: 102,568 entries; per user ~2,051 entries, 17 subdomains, 35 websites.
  3. Query sets (§3.2, Tab.2) — Level 0 states website and preference values explicitly; level 1 masks the website; level 2 masks both. Only 3.56% of history entries contain a preference value as an exact string match, so masked slots cannot be filled by string search.
  4. Validation (App.A.2) — GPT-5 checks seeds and actions for instruction adherence, temporal consistency, and preference alignment; human annotators review every profile on five criteria. Diversity: topic entropy 4.503 (max 4.605), Shannon evenness 0.978, cross-user cosine distance 0.626, per-user Ent-4 9.932. Realism: six judges prefer these histories over single-pass generation at 88.3% (sequence) and 98.3% (entry) win rates, Gwet's AC1 0.72 and 0.97.

Personalization module (§4, App.C). The planner decides at each step whether history is needed and emits a history query; the retriever (Stella V5 1.5B dense embeddings, FAISS inner product, entries keyed by type + object, up to 20 results above 0.5 cosine similarity) returns entries; the generator reasons over them into a personalized rationale that conditions subsequent actions. AgentOccam runs on Playwright/Chromium starting from bing.com; Browser-Use switches to DuckDuckGo at CAPTCHAs; both use text-only observations (no screenshots) for fair comparison.

Rubrics (§3.3, App.E). Pweb: 10 points = 5 retrieval + 5 utilization (did the agent find the habitual website in history, and did it navigate there). Ppref: 2.5 points × 2 preferences × 2 stages, plus a conditional 5-point location rubric on location-aware sites (Amazon, Resy, OpenTable), normalized. Intent satisfaction: 10 for full completion, 5 when the correct decisive action is blocked by external factors (out of stock, CAPTCHA, site error), 0 otherwise. SR counts only trajectories perfect on everything.

Judge validation (§5.1, App.B). Against three human annotators on 50 held-out queries, reasoning-aware judging beats action-wise and outcome-based judging on every metric, with the gap concentrated exactly where it matters: preference personalization (Pearson 0.72 vs 0.40 vs 0.23; Tab.6), because only reasoning traces expose the retrieval stage. GPT-5-mini re-scores consistently (std at most 0.015; Tab.13); three heterogeneous judges (GPT-5-mini, Qwen-80B-Instruct, GPT-OSS-120B) agree at Krippendorff’s α 0.80–0.84 for Pweb and 0.74–0.79 for Ppref, but only 0.61–0.68 for intent (Tab.14) — and humans themselves agree least on intent (AC1 0.743; Tab.12).

Main result

On the target level-2 queries, every no-history configuration scores 0% SR, and the best history-enabled configurations — Browser-Use with o3 (on-demand) or GPT-4.1 (either scheme) — reach only 13% (Tab.5, p.7). History access lifts average personalization from Pavg 0.03–0.17 to 0.36–0.77, so agents do extract preference signal; converting it into a completed, correctly personalized task is what fails. o3 and GPT-4.1 achieve 6–13% SR while open-source backbones stay at or below 5% (§5.3) — with Gemini-2.5-Flash landing in the open-source band (0.00–0.03) despite being proprietary. Repeated runs are stable (max std 0.025 over three executions; Tab.8).

Key findings

  • Without history, ambiguity is fatal in two architecture-specific ways (§5.3, Tab.5): AgentOccam substitutes random plausible values and pushes to completion (intent 0.24–0.50, roughly twice Browser-Use’s), while Browser-Use requests clarification and abandons (intent 0.09–0.28). A completion-style eval would rank AgentOccam higher; the personalization lens ranks Browser-Use higher (it owns every SR of 0.10 or more) — the metric flips the architecture ranking.
  • Browser-Use beats AgentOccam on personalization scores for all five backbones once history is available (Tab.5, App.C.1), which the authors attribute to observation construction: AgentOccam’s pruned accessibility tree discards context that personalization needs, while Browser-Use keeps a full enhanced DOM tree.
  • Identical success rates hide opposite failures (§5.3): Browser-Use + Llama-3.3 (pre-execution) personalizes but cannot navigate (Pavg 0.680, intent 0.197); AgentOccam + Gemini-2.5 (on-demand) navigates but does not personalize (intent 0.403, Pavg 0.486). Both land on SR 0.02 — the decomposed metrics exist because SR cannot tell these apart.
  • Success drops monotonically with ambiguity (averaged over o3, GPT-4.1, Qwen3-80B): 23.8% at level 0 → 16.3% at level 1 → 7.8% at level 2 — despite the module and history being available throughout (Fig.3, §5.4); and even clear queries leak personalization (preference 0.92, website 0.97): agents drop one of several explicit constraints (SSD capacity and port filters applied, the under-120-USD budget ignored) or apply information at the wrong execution step.
  • Making context explicit largely dissolves the benchmark (Tab.7, §5.5): swapping raw history for the explicit profile lifts Browser-Use + GPT-4.1 to SR 0.27 (+0.14, pre-execution) and Ppref to 0.892 (+0.206) — the difficulty lives in implicitness, not context volume. Backbones also specialize by access scheme: GPT-4.1 is consistently better on-demand, Qwen3-80B and Llama-3.3 pre-execution (§5.3).
  • History retrieval failure dominates personalization errors (about half in the Gemini-2.5-Flash breakdown), ahead of utilization failure and redundant access; hallucination is least frequent (§6, Fig.5): the retriever misses “Baltimore Orioles” as the favorite MLB team because no entry says “favorite team”; a retrieved Los Angeles location never gets applied to the concert search. Retrieval is also config-sensitive: keying the index on type + object beats keying on all four fields (Ppref 0.677 vs 0.480 on-demand; Tab.15).

Implications

Personalization here turned as much on harness plumbing as on the backbone — index-key design, access-scheme choice per model, and observation construction each moved scores — which makes user history a design surface for agent harnesses, not just extra prompt tokens. As a benchmark it takes the open-web site pools and LLM-judge pattern of Mind2Web, WebArena, and WebVoyager and adds the user-context axis all of them lack (Tab.1); its nearest personalization neighbors, PersonalWAB (function calls) and Apollonion (dialogue), never touch real navigation. When-to-retrieve policies and memory architectures beyond dense retrieval — the Orioles miss is a semantic-linking failure no similarity threshold fixes. Whether native memory tooling in agent frameworks outperforms this bolt-on planner–retriever–generator module. The same group’s AgenticShop (WWW 2026) for the shopping-specific slice of personalized agents.

Limitations

  • Fully synthetic personas and histories: GPT-4o generates profiles, events, and entries; realism is validated only pairwise against a weaker single-pass synthetic baseline (88.3%/98.3% win rates), never against real browsing logs. Profiles are internally consistent by construction — real users are contradictory, multi-device, and drifting; the 10% cancellation noise is the only injected messiness.
  • LLM-judge validity is weakest exactly where tasks die: intent satisfaction has only tentatively acceptable inter-judge agreement (α 0.61–0.68) and the lowest human IAA (AC1 0.743), yet SR requires a perfect intent score, so judge noise compounds into the headline metric. The retrieval rubric also credits whether the expected value appears in any memory response — partly measuring the fixed retriever rather than the agent.
  • Generator-family overlap is uncontrolled: histories are written by GPT-4o, judged by GPT-5-mini, and the best agents are GPT-4.1/o3 — whether OpenAI-styled preference encodings are easier for OpenAI models to decode is never tested (open-source judges agree on scores, but generation-side bias is a different question).
  • Live-web instability undercuts the strict metric: between the December 2025 and March 2026 runs, GPT-4.1 SR fell from 0.13 to 0.022 (on-demand) and 0.018 (pre-execution) — the paper frames this as stability because component scores moved little and rankings held, but the absolute headline number is not temporally comparable (Tab.8–9).
  • Scale and determinism: 150 queries (about 50 per level), 2 architectures, main-table numbers from single executions (repeats exist only for two Browser-Use configs), and every masked slot has exactly one expected value — personalization is scored as recovering the planted preference, not as choosing among defensible alternatives. Compute/token cost of the two access schemes: Not reported.

Critiques and Questions

  1. The reproducibility claim is spun: “results remain consistent despite open-web dynamics” holds for Pweb/Ppref and for rankings, but the metric the abstract leads with (SR) dropped by more than 80% relative in three months, and intent moved +0.176. This benchmark supports ranking claims, not absolute-progress claims — worth saying plainly when citing it.
  2. “First personalized web-agent benchmark on the real open web” is qualifier-load-bearing: the same group published AgenticShop (WWW 2026) for personalized agentic shopping, and PersonalWAB (WWW 2025) already did history-based personalization without navigation. The genuine delta — live multi-domain navigation with implicit history — is real but narrower than “first” suggests.
  3. Is 13% a capability ceiling or a metric artifact? Intent gives partial credit (5 points) when an agent is blocked externally, but SR does not inherit it: a perfectly personalized run blocked by an out-of-stock item scores SR 0. A relaxed SR (perfect personalization + intent of at least 5) would separate “cannot personalize” from “the open web got in the way”.
  4. All agents share one retrieval interface (Stella top-20 at 0.5 threshold). The headline error mode — retrieval failure, about half of personalization errors — may be an artifact of this specific retriever; the App.F ablation varies only the index key, never the retriever, the threshold, or agent-controlled search over raw history.
  5. Scoring the fabricated “4 stars and up” filter as hallucination presumes the planted preference is the only correct answer; for a user whose history is silent on rating thresholds, a generic-prior default is arguably rational agent behavior. The rubric equates personalization with exact recovery of generator-planted values.
  6. Gemini-2.5-Flash performs at open-source level (SR 0.00–0.03), so the “proprietary vs open-source” framing is really an o3/GPT-4.1 effect; and with roughly 50 level-2 tasks, several Table 5 rows are separated by one or two tasks.
Two configurations in Table 5 both score SR = 0.02 — why does the paper treat this pair as evidence that task completion alone cannot measure personalization?
They fail for opposite reasons. Browser-Use with Llama-3.3-70B (pre-execution) reaches Pavg 0.680 but intent 0.197 — it infers the user's preferences but cannot execute the navigation — while AgentOccam with Gemini-2.5-Flash (on-demand) reaches intent 0.403 but only Pavg 0.486 — it navigates passably but does not personalize. Identical success rates, opposite bottlenecks; only trajectory-level scoring that separates personalization (retrieval + utilization) from intent satisfaction can attribute the failure.

Personal notes

Steal for the harness: (1) log memory access as first-class trajectory events — the whole evaluation works only because history queries and retrieved entries are recorded, making retrieval vs utilization failures separable post hoc; (2) index memory by content fields only (type + object) — timestamps/URLs in the embedding key measurably hurt (Tab.15); (3) history-access policy is a per-model harness knob (GPT-4.1 wants on-demand, Qwen/Llama want pre-execution). Treat the benchmark as ranking-stable but not level-stable: strict SR fell 0.13 → 0.022 over three months of site drift. Code/data: serin-kimm.github.io/Persona2Web (per abstract). Related to chase: PersonalWAB (WWW 2025), AgenticShop (WWW 2026, same group), Mind2Web 2 agent-as-a-judge.
