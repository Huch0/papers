Curated byChiyeong Heo

A weight-free self-play harness for two-player LLM games that optimizes only the inference-time context — tournament-style prompt evolution selected by a TrueSkill lower-confidence bound, a persistent CRUD-maintained memory bank of trajectory-distilled insights injected as priors, and prioritized replay of rare states — roughly doubling mean win rate (25.1→49.5% GPT-4o-mini; 20.9→44.3% Qwen2.5-7B) within 2,000 self-play games per task.

Squarely harness engineering: every gain comes from optimizing prompt + memory around frozen models, with RL as the explicit comparison point. Its evaluation angle — trivial prompt rewordings flip multi-agent leaderboards — is direct ammunition for my agent-benchmark run-to-run-variance concerns. ICML 2026 poster; advisor-review pick.

Motivation

Multi-turn, multi-agent LLM game evaluations have substantial run-to-run variance: each output becomes the next input, so small early deviations compound into divergent trajectories; multi-agent coupling amplifies them (one agent’s inconsistency perturbs the other’s best responses); and some LLMs are nondeterministic even under nominally deterministic decoding (§1). This biases win-rate estimates and destabilizes rankings across repeated tournaments. The paper quantifies the prompt half of the problem: five semantically equivalent stylistic rewordings of the Kuhn Poker prompt (gladiator / technical / spiritual / casual / spy themes) reshuffle a six-frontier-model round-robin leaderboard — pairwise Kendall’s τ between prompt-variant leaderboards spans 0.50 down to −0.50 (Appx.A, Fig.5). Meanwhile automatic prompt optimizers (TextGrad, MIPRO, GEPA) were built for static tasks: they update from a local batch of trajectories and retain nothing across rounds, so in path-dependent games — where different tournaments surface different decisive states and rare failure modes — the optimization itself becomes run-dependent and high-variance.

Contribution (what’s new)

Treat the game context (system prompt + injected memory) as the optimization target, and make the optimizer cumulative: a persistent memory bank of insights distilled from completed self-play trajectories, merged CRUD-style (add if novel, merge if similar, delete both on contradiction) across generations and injected as inference-time priors into 75% of candidates. The form is forced by why GEPA-style evolution fails here: memoryless prompt search rediscovers and forgets game-specific lessons every run. Two supporting mechanisms handle game noise: uncertainty-aware candidate selection via a TrueSkill lower-confidence bound (μ − kσ), because raw win counts over ~50 games confuse luck with skill, and prioritized replay of rare trajectory prefixes (inverse-frequency priority, stored with environment seeds), because decisive states will not recur by chance. The ablation is the argument: exploration alone +3.3 points, memory alone +10.4, combined +24.3 (Tab.3).

Research questions

(1) How sensitive are multi-turn multi-agent game outcomes and rankings to inference-time context? (2) Can context optimization alone — no weight updates — match RL self-play, and at what interaction budget and run-to-run stability? (3) Which ingredient drives gains: structured exploration (tournament + replay) or retention (persistent memory)? (4) Do optimized contexts transfer zero-shot across games and across models?

Methodology

Formalized as a two-player, turn-based, zero-sum, partially observable Markov game; the context is the pair (instruction prompt, injected memory). MEMO maintains 8 candidate contexts over 5 generations. Each generation: every candidate plays 50 self-play games against a fixed anchor — the same base model running the default prompt (roles swapped in asymmetric games) — then TrueSkill-LCB scores pick survivors into a persistent elite pool. Discarded slots are refilled by random style-guided prompt edits or memory-augmented edits. After each generation, the model reflects on sampled trajectories (the template targets the highest-outcome-variance states) to extract typed insights that are CRUD-merged into the bank; 75% of next-generation candidates get a sampled subset appended, and 40% of games resume from prioritized replay prefixes. Total: 2,000 games per task. Five text games from TextArena and SPIN-Bench.

Method details, hyperparameters, and evaluation protocol
  1. Tournament + uncertainty-aware selection (§3.1) — Population N=8. Each candidate plays 50 games/generation against the fixed default-prompt anchor (two role-swapped games per round in asymmetric games). TrueSkill models each candidate's skill as a Gaussian; survivors are kept by the lower-confidence bound S(c) = μ − kσ with k=1, penalizing high-uncertainty candidates so a lucky 3-for-3 cannot displace a reliably strong context. A persistent pool P retains the best contexts across generations; the final output is the highest-scoring member of P.
  2. Context proposal operators (§3.1, Appx.D) — Refill via (a) random proposals: sample one of ~45 catalogued playstyles (aggressive, minimax-oriented, deceptive, trap-setting, ...) and apply length-bounded edits to the base context that must preserve legality and interface constraints; (b) memory-augmented updates: targeted prompt edits conditioned on insights sampled from the bank. Generation 0 is all-random (empty bank).
  3. Reflection into the memory bank (§3.2, Appx.E–F) — After each generation the model reviews sampled completed trajectories — states with the highest win/loss variance — and emits typed insights (rule clarifications, legality constraints, strategy priors). Merge operations: ADD if not similar to any stored insight; EDIT to merge/generalize similar ones; REMOVE both sides of a contradiction. At the next generation a compact subset is appended to ρ=75% of candidates at inference time; the same bank also conditions the memory proposal operator. Bank size and subset size: not reported.
  4. Prioritized replay (§3.3) — Buffer of capacity 100,000 stores trajectory prefixes turn-by-turn with the environment seed; invalid moves are kept to preserve the true course of play. Sampling weight is inverse-frequency priority raised to α=0.6; with probability β=0.4 a game resumes from a sampled prefix instead of starting fresh. Sensitivity (Tab.5–6, TwoDollar): β is the most sensitive knob — always-replay (β=1.0) collapses to 31.1% vs 61.1% at β=0.4; the largest tested buffer wins; intermediate ρ in 0.25–0.75 beats both extremes.
  5. Budget and evaluation (§4.2–4.3) — One fixed configuration everywhere (no per-task tuning): 8 × 5 × 50 = 2,000 self-play games per task. Evaluation: 3 independent optimization runs; each final context plays 50 games × 3 held-out opponents (Grok-4-Fast-Non-Reasoning, Gemini-2.5-Flash-Lite, Qwen3-235B-A22B-Instruct-2507) at temperature 1.0. Reported: mean win rate and mean per-game RSE across runs. Baselines: TextGrad/MIPRO/GEPA are author-adapted to games via offline tournament trajectories and action-matching scoring rules (Appx.H); RL baselines (UnstableBaselines = LoRA + REINFORCE, SPIRAL) train a single policy and evaluate the best checkpoint over three 50-game sets.

Main result

On GPT-4o-mini, MEMO reaches 49.5% mean win rate vs 25.1% for the default prompt and 36.7% for the best prompt-optimization baseline (MIPRO), with the lowest mean RSE (6.4% vs 44.9% baseline) (Tab.2, p.8). On Qwen2.5-7B, MEMO reaches 44.3% — 0.7 points below the RL baseline UnstableBaselines (45.0%) on mean win rate, but using 19× fewer games (2,000 vs 38,000) and with RSE 6.1% vs the RL run’s 43.3% (Tab.2, p.8). A third base model replicates the direction: Gemini-2.5-Flash improves 27.4%→40.8% (no RSE reported) (Tab.14).

Key findings

  • Memory is the dominant mechanism; exploration alone barely helps (Tab.3, p.9): over a 23.8% three-game base, tournament-only adds +3.3, memory-only +10.4, tournament+memory +24.3, and replay a further +2.1 to 50.2% — retention turns memoryless prompt search into cumulative learning (table below).
  • Sample- and token-efficient vs alternatives (Fig.1b; Tab.11): 60% on Kuhn Poker at 2,000 games where RL needs 38,000 (Qwen); optimizer output-token cost 91K vs MIPRO 354K and GEPA 114K (TextGrad uses ~1K but cannot learn multi-turn behavior). Gameplay tokens for the 2,000 games are excluded from this accounting.
  • Where MEMO wins tracks game type — and RL keeps two games (Tab.2): largest MEMO gains in negotiation and Kuhn Poker; UnstableBaselines beats MEMO on Briscola (53.3% vs 31.1%) and SimpleTak (47.3% vs 34.0%) on Qwen. The abstract’s “RL remains more effective in perfect-information settings” undersells that Briscola — an imperfect-information game — is also an RL win.
  • Optimized contexts transfer zero-shot across games, asymmetrically (Tab.4, p.9): SimpleTak→KuhnPoker +25.9 points and TwoDollar→SimpleTak +26.4, but Briscola→SimpleTak −7.1; protocol-level skills (turn management, action formatting, short-horizon planning) travel while payoff-specific heuristics need structural overlap.
  • Cross-model transfer helps weaker models and can hurt stronger ones (Fig.4, p.10): a GPT-4o-mini-optimized context lifts Gemini-2.5-Flash-Lite on all three tested games (up to +35 on TwoDollar) but drops Grok-4-Fast on exactly its strongest games (−8.0 Briscola, −6.0 Kuhn Poker) — transferred heuristics fill capability gaps but conflict with native strategies.
  • Stored insights encode strategy, not trivia (Appx.M): pressure-based betting balanced against hand strength (Kuhn), probing the opponent’s asymmetric resource valuations before offering (SimpleNegotiation — a fact never stated in the rules), and deadline-pressure tactics (TwoDollar).

Implications

Reframes evaluation context as an optimizable part of the measured system rather than a fixed wrapper — for harness work, the actionable reading is that a large share of “model capability” in interactive settings is actually context quality. It extends the experiential line of ReAct → Reflexion → ExpeL (persistent insight rules for static tasks) into adversarial multi-agent games, and tempers GEPA’s “reflective prompt evolution can outperform RL” claim: in path-dependent games, evolution without retention loses badly (GEPA 32.0% vs MEMO 49.5% on GPT-4o-mini), and persistent memory is what closes the gap. For evaluation practice it argues — with Mizrahi et al.’s multi-prompt evaluation call — for prompt-variation reporting over single-prompt leaderboards. The obvious missing experiment: re-run the Appendix A Kendall-τ ranking study with MEMO-optimized contexts to actually test the “stable rankings” claim. Port the TrueSkill-LCB candidate gate and the CRUD memory bank to non-game agent harnesses (SWE/web agents), where run-to-run variance has the same compounding structure. Hybrid split suggested by Tab.2: RL weights for perfect-information planning, context+memory for negotiation and hidden-information games.

Limitations

  • Games only, and small ones: five two-player zero-sum text games (Kuhn Poker has 3 cards; SimpleTak is a 4×4 board); base models are small (GPT-4o-mini, 7B) and opponents are non-reasoning tiers. Nothing shows the recipe on open-ended agent tasks.
  • Variance reduction is not demonstrated separately from win-rate gains: RSE divides by the mean and the per-game average is dominated by near-zero-mean games (baseline Briscola 0.3%). Recomputing absolute per-game std from Tabs.7–9/12 (GPT-4o-mini): MEMO averages 5.3 points ≈ MIPRO 5.3, above GEPA 3.2 — the “most stable” headline rests on the relative metric.
  • The ranking-stability claim is never measured post-treatment: the abstract promises “more stable rankings across prompt variations”, but the Kendall-τ experiment exists only for unoptimized contexts.
  • The 19× efficiency figure is one game and one model (Kuhn Poker, Qwen; Fig.1b), with the RL games-to-60% read off a single training run.
  • Everything rests on 3 runs, with no significance testing; compute cost beyond optimizer tokens — 2,000 multi-turn games per task per run, both players billed, across 5 games × 2 models × 3 runs plus ablations — is not reported in dollars or wall-clock (the acknowledgments thank two organizations for covering experiment costs).
  • Optimization plays a fixed default-prompt copy of the base model, and per-opponent robustness is weak: Tab.13 shows MEMO’s SimpleNegotiation win rate is 94.0% vs Gemini-2.5-Flash-Lite but 30.7% vs Grok-4-Fast (std across opponents up to 37 points) — “robust” means run-to-run, not opponent-to-opponent.

  1. The stability story is the paper’s most quotable claim and its weakest measurement. Is there any matched-mean comparison where MEMO shows lower absolute dispersion than a baseline? The released tables cannot answer it, and the baseline’s per-trial data (needed for its absolute std) is not published at all.
  2. Internal inconsistencies worth raising: Qwen MEMO Briscola/SimpleTak are 31.1/34.0 in Tab.2 but 31.5/36.9 in per-trial Tab.12 (mean 44.3 vs 45.0), and the printed 6.1% RSE is not reproducible from Tab.12’s stds (I get ~7.0); Table 4’s caption says columns = source game while the header (“Training Game”) and three of four in-text examples imply rows = source; the intro’s “6.4% compared to 43.3%” pairs a GPT-4o-mini number with what is actually the RL baseline’s RSE (the static baseline’s is 44.9%).
  3. Baseline strength is author-implemented adaptation: MIPRO/GEPA are driven by an action-matching proxy score the authors themselves argue is ill-defined for games, so part of MEMO’s margin over them may be adaptation quality rather than method. SPIRAL is missing 2 of 5 games with no explanation.
  4. Generality of the harness is less turnkey than presented: the released reflection/memory prompts (Appx.E–F) are board-game flavored (“cell 3”, X/O board-reading guides), and per-game instantiation is not described. Also unreported: bank size over time, injected subset size, trajectories reflected per generation.
  5. Outcome adjudication and contamination: TwoDollar’s victory condition includes “reach any deal while being appropriately sympathetic” — who or what judges sympathy is unspecified, a potential judge channel in one of five games. And Kuhn Poker’s equilibrium strategy is textbook material almost surely in pretraining data, so some memory “insights” (bet more with K) look like elicitation of memorized strategy rather than discovery — harmless for method comparison, but it inflates the learning narrative.
Why does MEMO select surviving prompt candidates with a TrueSkill lower-confidence bound rather than raw win rate, and who is the opponent during optimization?
With ~50 stochastic games per candidate per generation, raw win counts confuse luck with skill — a 3-for-3 context may just be lucky. TrueSkill models each candidate's skill as a Gaussian (μ, σ) and MEMO keeps candidates by S(c) = μ − kσ with k=1, penalizing uncertainty so only reliably winning contexts survive. During optimization every candidate plays a fixed anchor: the same base model running the default prompt (roles swapped in asymmetric games); the three held-out opponent models appear only at evaluation time.

Personal notes

Three things to steal for our harness work: (1) the TrueSkill-LCB gate as a cheap selection rule for any noisy A/B over agent configs; (2) the Appendix A protocol — five stylistic prompt paraphrases + Kendall-τ across leaderboards — as a ready-made audit for our own multi-agent evals; (3) the RSE lesson in reverse: never report mean-normalized variance when means differ, since lifting the mean masquerades as stabilizing. Discussion point for advisor: MEMO is essentially GEPA + ExpeL-style persistent memory + prioritized replay glued by TrueSkill — the delta is integration, not any single new idea, but the ablation (+3.3 exploration vs +10.4 memory) is a genuinely useful decomposition for harness design. Open question I’d push on: everything is optimized against a fixed default-prompt self-opponent; does the memory bank encode the game or the anchor opponent? The 94% vs 30.7% per-opponent spread suggests some of both. Code: github.com/openverse-ai/MEMO.
