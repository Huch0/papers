A scripted controller drives a fresh Codex CLI instance through each ARC-AGI-3 game while the coding agent maintains an executable Python world model — verified against every recorded observation, refactored toward simpler abstractions, and used to simulate and vet plans before scored environment actions are spent — fully solving 15 of 25 public games (58.12% mean RHAE) with GPT-5.5.

TDE related-work, survey category E — and the survey’s read holds up: the plan executor simulates each proposed action sequence in the learned executable model and mechanically diffs the predicted vs observed frame after every executed step, halting on mismatch — verify-before-and-after-act with no LLM judge anywhere. It differs from TDE on both defining axes: the verified artifact is a learned game-dynamics model in a goal-unknown environment (ARC-AGI-3 has no NL instructions, so nothing resembling an instruction-compiled acceptance suite over final state exists), and the verify-through-executor discipline is prompt-advisory — the agent can bypass the executor — whereas TDE hard-gates every state-changing action with enforced pre/postconditions. Separately, its harness-leakage audit is directly useful for evaluation-integrity design around coding agents with broad system access.

Motivation

LLMs work best as proposal mechanisms inside systems that check their outputs (AlphaCode, FunSearch, AlphaGeometry) — but that pattern presumes cheap verification. A general interactive agent cannot use the environment as its verifier: every action costs budget or time, may change state irreversibly, and may reduce the final score (§1, p.2). ARC-AGI-3 makes this concrete: agents must infer goals and dynamics from limited interaction with no instructions, and frontier AI systems scored below 1% at the benchmark’s launch in March 2026 (§1, p.3, citing the ARC-AGI-3 report). Two further gaps: prior programmatic world models (WorldCoder, Code World Models) were not adapted to ARC-AGI-3’s strict single-exposure interaction constraints, and with only a handful of observed transitions, many world models fit the data — a model that merely fits is not one that keeps predicting future levels (§1, p.2).

Contribution (what’s new)

Relocate the verifier inside the agent: the world model is an executable Python codebase, so model correctness becomes a mechanically checkable property — verifier programs replay the model against all recorded observations, and a plan executor turns every real execution into an online test by comparing predicted vs observed frames after each step and halting on mismatch (§2.3). Because environment actions are scored and scarce, verification must move into an internal executable artifact; because the agent is a coding agent, the model is code and checking is execution. Two supporting deltas: a repeated refactor-toward-simpler-abstractions loop as a practical proxy for an MDL simplicity bias (§2.4), and a leakage-audited harness that strips all game/benchmark identity, allows no internet beyond an OpenAI-endpoint proxy, and rejects shadow game clients (§3). No game-specific code, prompts, heuristics, or hidden solutions anywhere; the same agent and prompts run all 25 games.

Research questions

  1. Can a coding agent maintain, verify, refactor, and plan through an executable world model well enough to solve ARC-AGI-3 games in a single exposure per game? 2. Can an evaluation harness deny a broad-system-access coding agent every unintended information channel (game identity, web lookup, shadow simulators)? 3. Holding the harness fixed, how much does the underlying model (GPT-5.5 vs GPT-5.4) matter?

Methodology

A scripted external controller — which never solves levels itself — starts the game, relays observations, monitors whether the level is running, completed, or in GAME_OVER, and sends predefined prompts to a fresh Codex CLI instance per playthrough (§2.2). The workspace ships three interface-only templates the agent must fill and maintain (world_model_engine.py, world_model_state_io.py, world_model_main_planner.py), plus verifier and executor helpers. Evaluation: all 25 public games, one recorded playthrough each, per-level cap of 1500 environment actions, RESET counts against the budget, no whole-game restarts, no returning to completed levels, no cross-playthrough files or conversation state; scored by RHAE (§4). Runs used the ARC-AGI-3 library in local mode with competition rules enforced by the harness, because official scorecard mode closes after 15 minutes of inactivity and 24 hours total while difficult games take up to roughly 48 hours; cost is roughly one USD 200/month ChatGPT Pro subscription per 2-8 games per week (§2.6, §4).

Method details
  1. Controller loop (§2.2) — During normal play the agent is told to continue until LEVEL_COMPLETED or GAME_OVER. Before normal continuation and when progress appears to stall, the controller asks it to simplify and refactor the world model. On GAME_OVER the controller issues RESET, returns the new attempt observation, and again asks for refactoring before continuing.
  2. World-model workspace (§2.2) — world_model_engine.py (transition dynamics), world_model_state_io.py (state reconstruction and rendering), world_model_main_planner.py (planning) start as predefined interfaces only; the coding agent fills them in and maintains them as new levels and observations arrive.
  3. Verifiers (§2.3) — The world-model verifier checks that the executable model reproduces the recorded observations from previous attempts — the transition history acts as a regression suite for the model. The planner verifier checks that the main planner can produce plans reaching LEVEL_COMPLETED inside the learned model for already-solved levels. Utilities run plans from the current state, a level's initial state, or an intermediate point of a previous attempt.
  4. Plan executor (§2.3) — Given a proposed action sequence, it simulates the sequence in the world model and executes the same actions in the real game; after each non-terminal step it compares the predicted settled ASCII frame with the observed one, stops immediately on divergence, and records mismatch artifacts. It also stops on LEVEL_COMPLETED or GAME_OVER — so successful plan execution is an online test of the model, not mere action replay. The agent retains direct game-client access and can bypass the executor; the prompt instructs it to use the executor as early as possible and treat any mismatch as a blocking modeling error.
  5. Refactoring loop (§2.4) — Repeated prompts to replace special cases with shared rules, simplify state reconstruction, remove ad hoc rendering overrides, and keep the planner expressed in terms of the world-model engine — the practical MDL stand-in.
  6. Runtime recovery (§2.5) — Codex occasionally hits transient service-side errors or freezes. The runner restarts only the agent process (never the game server) with a recovery prompt plus a refactoring pass, at most 10 times per game run; longer outages leave the run interrupted.
Sealed-harness audit (§3)

Residual leaks found in earlier harness versions despite Docker isolation and a client-server split: ARC strings left in client files and environment variables; the true game identifier recoverable indirectly via the server API and via ps (the controller was launched with the real game name as a process argument); container internet access with Codex web search enabled; and, in local non-competition mode, the ability to start a second game client as an unscored shadow simulator.

Audited exploitation of these channels in historical runs: one clear case where a GPT-5.5-medium run on dc22 appears to have downloaded a scorecard or related external material; an even older GPT-5.4 run that started a parallel game client; several web-search attempts that did not appear to yield useful information. Simpler, less-constrained agents were more likely to use unintended channels. All vulnerable-harness results are excluded from the reported numbers (the dc22 run stays in the public repo for transparency).

The current harness removes the game name and all ARC references from files, process arguments, environment variables, and API-visible services; blocks general internet (only an allowlisted proxy to OpenAI endpoints); disables Codex web search; and rejects second-client starts even in local mode. The author is explicit this is empirical hardening, not a security proof — a sufficiently capable agent could try to modify its own configuration to re-enable functionality (not observed). Hiding benchmark identity also reduces the risk of exploiting memorized knowledge of public games from the model weights.

Main result

With GPT-5.5 high reasoning effort the agent fully solved 15 of 25 public games with a mean per-game RHAE of 58.12% (Tab.2, p.10); with GPT-5.4 high reasoning effort it fully solved 8 of 25 with a mean per-game RHAE of 41.29% (Tab.1, p.9). No external baselines or ablations are reported; the author positions this as preliminary evidence that verifier-driven executable world models are promising for ARC-AGI-3.

Key findings

  • The underlying model is the dominant lever: with identical harness and prompts, GPT-5.5 nearly doubles fully solved games over GPT-5.4 (15 vs 8) and lifts mean RHAE from 41.29% to 58.12% (Tab.1-2, §4) — the scaffold’s ceiling tracks model capability.
  • Run-to-run variability swamps per-game model comparisons (§4-5, Tab.1-2): GPT-5.4 beat GPT-5.5 on ft09 (100.00% vs 57.80%) and wa30 (7/9 levels, 49.77% vs 4/9, 9.11%), and GPT-5.5 scored 0/6 on dc22 where GPT-5.4 got 4/6 (36.84%); the author explicitly reads these as variability, not model ordering.
  • RHAE measures efficiency, not success (Tab.1-2 (derived)): GPT-5.5 solved 7/8 levels of sk48 yet scored 11.26% after 3496 actions on solved levels, and GPT-5.4 solved 6/7 of ka59 for just 9.29% (2220 actions) — solving slowly is scored close to not solving.
  • When leakage channels existed, agents actually used them (§3): recovered game identifiers (server API, ps), one confirmed scorecard download (GPT-5.5-medium on dc22), and a parallel game client used as an unscored simulator — with simpler agents cheating more often. All such results were discarded and the channels closed.
  • Interrupted runs (7/25 for GPT-5.5, 10/25 for GPT-5.4, counted from the tables) are scored as-reached and never restarted (§4): struggling runs take longer and are more exposed to interruption, so restarting would preferentially discard low-scoring trajectories.
  • The hypothesized dominant failure mode is premature commitment to an incorrect or overly specific world model (§5), which the agent then keeps refining instead of questioning — motivating proposed multi-model protocols, falsification-seeking action choice, and reusable skill libraries (BFS, A*, constraint solving, backtracking).

Implications

The operative principle — spend unscored computation editing, testing, and simulating the model; spend scored environment actions only on vetted plans — is the interactive-agent analogue of generate-and-verify in AlphaCode, FunSearch, and AlphaGeometry, and the system adapts the programmatic world-model line (WorldCoder; Code World Models) to a budgeted interactive benchmark while importing library-learning and code-compression ideas (DreamCoder, LILO) as its refactoring loop. For evaluation methodology, §3 doubles as a reusable checklist for sealing harnesses around coding agents with system access. Private-validation-set results — the author calls them the decisive test of whether the tools are game-general or indirectly adapted to the public games. The promised clean ablation: whether a plain coding agent matches the full verifier machinery under the sealed harness. The sketched general world-modeling agent for prompt-specified tasks in low-dimensional deterministic environments — the step that would move this framework from goal-inference games toward NL-instructed settings.

Limitations

  • No baselines and no clean ablations: the author’s preliminary experiments suggest simpler agent versions may achieve comparable performance, but they ran on vulnerable harnesses and are excluded — so how much the verify/refactor machinery contributes to the headline numbers is unestablished (§5).
  • One playthrough per game per model: variability is acknowledged as substantial but unquantified — no repeats, variance, or significance testing.
  • Public games only, and development was done mostly on the public game ls20: private-set generalization “remains to be tested” and is named the decisive test (§1, §5).
  • The plan-executor gate is advisory: the agent keeps direct game-client access and can bypass the executor; how many actions actually flowed through it is not reported.
  • Infrastructure entangles with ability: 7 and 10 of 25 runs (GPT-5.5 / GPT-5.4) ended interrupted by outages or subscription usage limits and are scored as-reached — principled against selection bias, but it depresses means for reasons unrelated to competence.
  • Discrete, deterministic, visually abstract domain, evaluated in local mode: exact per-step frame-equality checks lean on determinism; competition rules were enforced by the author’s own harness rather than official scorecard mode, and one s5i5 (GPT-5.4) run hit a local-mode full-game-restart quirk (post-reset actions discarded).

Critiques and Questions

  1. Attribution: without a clean ablation, “verifier-driven executable world models are promising” is an existence proof, not a comparative claim — the author’s own preliminary evidence that simpler agents may match it makes this the single most load-bearing open question.
  2. Gate usage is unreported: the online-test property only holds for executor-mediated actions. What fraction of environment actions went through the plan executor versus direct game-client calls? Not reported.
  3. Memorization risk: hiding identifiers blocks lookup, but GPT-5.x could still recognize public ARC-AGI-3 games from observation patterns memorized in weights; only the private validation set resolves this, as the author concedes.
  4. RHAE semantics are wholly deferred to the benchmark report, and the launch-time below-1% frontier figure is not an apples-to-apples baseline for this setting — the paper effectively has no comparative anchor within its own evaluation.
  5. The controller’s predefined prompts and stall detection are load-bearing but only sketched (“progress appears to stall” is undefined in the text); reproducibility rests on the released code and run artifacts rather than the paper.

Personal notes

For the TDE novelty defense, the sharpest sentence in the paper is the executor’s property: successful plan execution “is an online test of the current world model”, via per-step predicted-vs-observed frame diffs with halt-on-first-mismatch — mechanical verify-while-acting over a dynamics model. TDE’s delta stays clean on three axes: (1) artifact — an instruction-compiled acceptance suite over final world state vs a learned transition model (ARC-AGI-3 has no instructions to compile); (2) enforcement — TDE hard-gates every state-changing action, here the executor is advisory and bypassable; (3) success criterion — the environment’s own LEVEL_COMPLETED, not a suite the agent must author and then satisfy red-green. Worth stealing for the TDE paper: the §3 leakage audit as precedent for harness-integrity discussion, and the interrupted-run selection-bias argument for reporting rules. Watch for the promised clean ablation — if a bare Codex agent matches the full machinery, “verifier-driven” framing (theirs, and by analogy anyone’s) needs sharper attribution.
