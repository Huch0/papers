Curated byChiyeong Heo

NeuSymMS is a production memory layer for LLM agents (inside the proprietary Nexa platform) that confines the LLM to parsing dialogue into subject–relation–value candidate facts and delegates every memory decision — classification, deduplication, contradiction resolution, and short-/long-term lifecycle — to a deterministic CLIPS rule engine; it is an architecture paper with no quantitative evaluation.

TDE relation (survey cat. I — confirmed against the paper): it shares TDE’s de-circularization instinct — the LLM only parses, and every adjudication is mechanical (CLIPS rules emitting auditable reason strings, never an LLM judge) — and it explicitly revives the Doyle/de Kleer truth-maintenance lineage that TDE positions itself as superseding. But its verifier faces inward: it enforces consistency among LLM-extracted memory facts, never correctness of world state — no executable acceptance suite, no pre/postcondition gating of state-changing actions, no task-completion criterion. A clean foil for the novelty defense: beliefs are checked against other beliefs, not against the environment, so mechanical ≠ grounded.

Motivation

Deployed LLM assistants behave as persistent agents but treat conversation history as ephemeral context. The paper sorts prior persistent-memory work into three families — conversation-log retrieval, LLM summarization, and key-value/knowledge-graph storage — and argues all three are noisy, expensive, and ill-suited to contradictions and temporal change in user state (§I, p.1). Specifically: retrieval pipelines (RAG, DPR) treat transcripts as immutable documents with no notion of user-level belief revision when information changes (§II, p.2); summarization sacrifices atomicity, so individual facts cannot be updated or retracted (§II, p.2); long-context models still degrade lost-in-the-middle style (§II, p.2); and knowledge-graph work motivates triples but not how to extract and maintain them over evolving dialogue in production (§II, p.2). Meanwhile, decades of mature symbolic machinery — rule engines, truth maintenance, expert systems — sit largely unused in modern agentic memory (§I, p.1).

Contribution (what’s new)

A division of labor placed exactly at the language/decision boundary: the LLM is used strictly as a parser that turns dialogue into candidate subject–relation–value triples, while every memory decision is made by a deterministic CLIPS forward-chaining engine that emits auditable engine-decision facts carrying reason strings (§I, §IV). The form follows the diagnosed failure: the weak point of prior families is the decision layer — where LLM judgment is nondeterministic and costly — whereas rules are deterministic, zero-API-cost, and inspectable, but cannot read language. Two supporting mechanisms: a dual-horizon (short-/long-term) lifecycle in which access_count is the importance signal — promotion at three accesses, time-based pruning — instead of a learned importance scorer (§IV.E, p.5), and three-tier user/agent/flow scoping where only user-scoped facts are ever injected into prompts (§III.C, p.3). Note the register: this is a production-architecture paper; the contributions are claimed properties of a deployed design, not measured results.

Research questions

Can classical expert-system machinery replace LLM judgment for agent-memory curation — deterministic, auditable contradiction handling and lifecycle management at near-zero marginal cost — with the LLM confined to language interpretation? Subordinately: where should the neural/symbolic boundary sit in a multi-tenant agent platform, and can cognitive-psychology-style dual-store lifecycles (rehearsal → promotion, decay → pruning) govern what an agent retains?

Methodology

NeuSymMS sits between user conversations and a provider-agnostic LLM gateway (LiteLLM). Pre-turn read path: query PostgreSQL for active, user-scoped triples; order by memory_type (long-term first), then access_count, then recency; cap the injection (e.g. 30 facts); format as a plain-text [Memory -- Known facts about this user] block in the system prompt. Post-turn write path: a lightweight extractor LLM (gpt-4.1-mini, temperature 0.1, at most 10 facts per turn) emits JSON candidates with subject, relation, value, confidence, scope; CLIPS 6.4 then runs three rule phases — classify, reconcile, store — whose decisions are applied to the fact table.

Method details
  1. Extract (§IV.A, p.4) — A lightweight LLM acts strictly as a fact-extraction engine over the turn, emitting a JSON array of candidate facts with subject, relation, value, confidence, scope. Negation must be encoded in the relation itself (no_longer_has, lost, stopped, died). If the extractor is unavailable, the system returns an empty fact list and the platform runs without memory rather than failing the request.
  2. Classify (§IV.C, p.4) — CLIPS rules pattern-match relation/value to assign one of nine semantic categories (personal, preference, task, relationship, skill, context, instruction, temporal, other; a catch-all rule labels the rest other). Claimed benefits of rules over an LLM here: determinism, microsecond-level latency, zero API cost, transparent pattern-to-category mapping.
  3. Reconcile (§IV.D, p.4-5) — Per request, only that user's active facts plus the candidates enter CLIPS working memory (no cross-user contamination). Values are normalized (lower-casing, Unicode normalization, punctuation/whitespace cleanup), then compared by Levenshtein similarity against a fixed 0.85 threshold to decide whether two values name the same entity. Same subject and relation with a different value: retract the old fact, store the new one (typically as long_term) — latest-value-wins for single-valued relations like works_at and lives_in. Multi-valued relations like speaks_language keep each distinct value as its own fact; a negation retracts only the matched value, and the negated form is never persisted.
  4. Store / promote / prune (§IV.E, p.5) — Pre-filters discard candidates with confidence below 0.3 and skip exact duplicates. Category rules auto-store personal, preference, instruction, and skill facts as long_term; other categories default to short_term with access_count initialized to 0. A short_term fact is promoted to long_term once access_count reaches 3; a background job deactivates short_term facts older than 24 hours with access_count 0. Temporal validity is represented only by creation/last-access timestamps — no validity intervals (deferred to future work).
  • Data model (§III.B, p.3): each fact is a triple plus scope (user | agent | flow), category, memory_type (short_term | long_term), confidence (0–1), access_count, source_text, timestamps, and an is_active flag for soft deletion (reversible deactivation, “historical analysis”).
  • CLIPS working memory (§IV.B, p.4): three core templates — memory-fact, candidate-fact, engine-decision (fact-id, action, reason) — plus a prompt-context template (keywords, intent, turn-number) “to support relevance-aware rules”; how prompt-context is actually used by rules is not detailed (Unclear).
  • Worked write path (§IV.F, p.5): “I just started a new job at Google in Mountain View. I speak Python and Go.” → four candidates → stored works_at Meta and lives_in Menlo Park are retracted and replaced as long-term facts; the two speaks_language facts are auto-promoted to long-term by category rules.
  • Read format (§IV.H, p.5-6): injected block lines look like [LT/skill] user speaks_language Python; ordering is long-term first, then access count, then recency.
  • Stack and ops (§V, p.6): Django REST Framework + PostgreSQL; CLIPSPy bindings run CLIPS 6.4 in-process; LiteLLM abstracts OpenAI/Anthropic/Google/Azure; a React Memory tab lets users view, search, filter, edit, and bulk-clear facts. Targeted indexes include (subject, relation) specifically to make contradiction lookup efficient.

Main result

There is none. The paper reports no quantitative results of any kind — “A full quantitative evaluation is left to future work” (§VII.A, p.7); §VI (“Results and Discussion”) is a qualitative recapitulation of the design’s claimed properties. The stated evaluation roadmap:

Key findings

No empirical findings exist; these are the load-bearing design-level claims, none empirically validated:

  • Claimed: memory decisions are zero-API-cost, low-latency, and rule-justified (§VI.A, p.6) — every engine-decision carries a reason string, giving an inspectable audit trail; no latency, cost, or throughput numbers are reported.
  • Belief revision is a deterministic retract-on-conflict policy (§IV.D, p.4-5): same subject+relation with a different value ⇒ retract old, store new; negations trigger retraction and are never stored. The paper presents this as mirroring Doyle/de Kleer truth maintenance, but there are no justification or dependency structures — nothing cascades.
  • access_count doubles as the importance model (§IV.E, p.5): rehearsal-style promotion (three accesses) plus 24-hour decay replaces the separate importance scorers of generative-agents-style memory, grounding salience in actual agent usage.
  • Isolation is by construction: only user-scoped facts ever reach a prompt (§III.C, p.3); agent- and flow-scoped facts are reserved for analytics and user inspection — this is the entire cross-entity-contamination defense.
  • Memory is an enhancement, not a dependency (§VI.B, p.6): extraction failure ⇒ no update; CLIPS failure ⇒ candidates stored as short-term; read failure ⇒ the agent answers without memory.
  • No embeddings anywhere (§IV.G, p.5): the read path is an indexed SQL query, capped and string-concatenated into the system prompt — explicitly contrasted with RAG/DPR-style retrieval pipelines.

Implications

NeuSymMS is the cleanest current example of re-importing the expert-systems stack — Forgy’s Rete, Doyle’s TMS, de Kleer’s assumption-based TMS, CLIPS itself — into LLM-agent memory, against the embedding-retrieval mainstream of Mem0, MemGPT, A-Mem, and generative-agents-style scored retrieval. Its load-bearing pattern — LLM-as-parser feeding a deterministic decision core — is TDE’s de-circularization move applied to a different object: NeuSymMS adjudicates the agent’s beliefs about a user, TDE adjudicates the environment’s final state. Internal consistency of a belief store is strictly weaker than mechanical verification of outcomes, because the fact base here is only as true as its LLM extractor. TELEMEM (contradiction-aware consolidation) and AMA-Bench/MEMORYARENA as the emerging evaluation surface for contradiction handling; whether the promised LoCoMo/LongMemEval evaluation materializes in a later version; open-vocabulary relation drift as the generic failure mode of rule-matched memory — what canonicalizes works_at vs employed_by?

Limitations

  • Zero empirical evaluation — no benchmarks, ablations, latency/cost measurements, or user data; author-stated (“left to future work”, §VII.A), so every property claim (contamination prevention, contradiction quality, cost) is untested.
  • Consistency without grounding: facts enter only via LLM extraction with self-reported confidence, and latest-value-wins ignores stored confidence — one wrong extraction silently overwrites a correct long-term fact; no fact is ever checked against an external source.
  • Contradiction detection fires only on an exact subject+relation match with string-similar values (Levenshtein 0.85): synonym relations (employed_by vs works_at), cross-relation contradictions, and non-lexical aliases escape it entirely.
  • Timestamps only — no temporal validity intervals; negation and uncertainty handling acknowledged as immature (§IV.E, §VII).
  • Single proprietary deployment (Nexa); no code, data, or artifacts released; single-team industrial provenance.
  • Manuscript hygiene is poor: unresolved macros in the PDF text (e.g. “tokenworksat”), typos, and placeholder references — [9] is literally marked “placeholder entry”, and LoCoMo is attributed to “J. Doe, A. Smith” in [6] while cited correctly as Maharana et al. in [33].

Critiques and Questions

  1. Determinism is only half the loop. The rule engine is deterministic, but its entire input — relations, values, confidences, scopes — comes from a temperature-0.1 LLM over an open vocabulary. Nothing enforces a closed relation ontology (classification even needs a catch-all rule), so end-to-end memory behavior is not deterministic; the paper never confronts this gap.
  2. The truth-maintenance framing oversells. Doyle/de Kleer systems track justifications and propagate retractions through dependency networks; NeuSymMS implements pairwise retract-on-conflict with latest-value-wins. Invoking TMS borrows authority the mechanism does not implement.
  3. For a system claimed to run in production, the absence of even operational statistics — fact volumes, retraction and promotion rates, measured read/write latency — is conspicuous; those need no benchmark, only logging.
  4. Privacy posture is thinner than claimed: soft deletion (is_active) retains data “for historical analysis”; whether the UI’s Clear All hard-deletes is not reported, yet the compliance story leans on that UI.
When a candidate fact conflicts with a stored fact, what exactly triggers a retraction in NeuSymMS, and which conflicts can it not see?
A retraction fires only when candidate and stored fact share subject and relation: for single-valued relations a different value means retract-old/store-new (latest-value-wins); for multi-valued relations, negation retracts only the value matched by normalized Levenshtein similarity at threshold 0.85. Conflicts expressed through different relations (employed_by vs works_at), non-lexical aliases, or paraphrased extractions never match a rule pattern, so contradictory facts coexist silently.
