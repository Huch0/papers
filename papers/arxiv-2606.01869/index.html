We score LLM-written Three.js worlds on what they do rather than how they look: 2,026 expert-curated tasks whose generated program must expose a window.__3D_STATE__ interface, probed in a sandboxed browser against hidden, mutation-hardened contracts over state deltas; the best of nine frontier models passes only 27.8% of assertions on WorldCoder-Core (Tab.1).

The closest published relative of a state/action contract for generated interactive programs — required state interface, deterministic scripted actions, programmatic assertions, mutation-tested checks — plus hard numbers on how badly DOM, screenshot, and agent judges do without one.

Motivation

Take our task P253 (Listing 1, App.D.2): a basketball free throw. Hold SPACE to charge power, set angle with the arrow keys, press ENTER; the ball flies under gravity −9.81 at a fixed 1/60 s step, and passing within 0.6 of the hoop centre increments score. A screenshot shows a ball arcing through a ring — the same picture whether score incremented, the radius test is right, or the trajectory depends on frame rate. Three.js paints positions, velocities, collision flags, and game phase into one opaque <canvas>; screenshots, DOM walkers, and external agents all observe from outside, so “looks right” stops being a proxy for “works right” (§1, §3.1). Prior web-generation benchmarks under-test physical correctness, asset integration, and engine–HUD synchronization (Fig.2, App.A). We measured the blind spot first: DOM scoring has per-pair Kendall τb −0.02 with hidden state-level correctness over 1,434 pairs, and an 8-turn agent at ∼400× the cost still passes 45.6% of severely defective worlds (§1, Tab.2).

Contribution (what’s new)

Make the world’s own state observable: the brief requires a window.__3D_STATE__ interface, and we verify by scripting actions and asserting on before/after state deltas against a contract the model never sees (§3.3). The canvas forces this — no other channel yields ballVelocity. A contract is admitted only after it rejects injected defects (stale updates, scaled constants, swapped event targets) (§3.2), so a pass measures behavior, not slack thresholds. Around this: 2,026 tasks, a perturbed Robust split, and two labor-denominated utility metrics, RoA and TEM (Eq.1).

Research questions

Can frontier models synthesize behaviorally correct 3D worlds from a brief? Does any external judge reproduce a state-level ranking? Where do worlds fail — scene, state, or transition? What is a partially correct world worth in labor?

Methodology

Walk P253 through StateProbe, our execution-based protocol (§3). The model gets task.json and assets/BarramundiFish.glb — never the action sequence, thresholds, or assertion scripts (§2.1) — and returns one HTML file. We load it in headless Chromium with a network-locked, version-locked Three.js archive and check executability (WebGL context, render loop, no early exception; else RUNTIME_CRASH). Then deterministic probes — key presses, clicks, drags, physics-step commands — each bracketed by before/after snapshots with assertions on the delta: phase must go idle → charging → flying → scored/missed, ballVelocity must follow the projectile, and score, shots, lastShotResult must agree with the HUD (§3.3, App.D.2). The run ends RUNTIME_CRASH, CHECK_FAIL, or CHECK_PASS with an auditable trace (state-contract verification).

What breaks without each piece:

  • State interface — without window.__3D_STATE__ there is nothing behind the canvas to read but pixels.
  • Hidden contract — a model that sees the action sequence and thresholds can special-case the probed transitions; contracts never enter prompts or leaderboard releases (§2.2, App.B.3).
  • Mutation-hardening — a slack contract (“score is a number”) passes a world whose hoop test never fires, so we inject stale updates, corrupted constants, broken asset loading, swapped event targets, and HUD mismatches and keep only contracts that reject every mutant (§3.2; see mutation-hardened checks).
  • Fixed timestep, physics-step commands — with wall-clock clock.getDelta() the ball’s position at probe step k depends on frame rate and the hoop assertion fires at the wrong moment: Qwen3.6-Plus’s P253 failure (App.D.2).
  • Locked runtime — otherwise a Three.js API change or a remote fetch (Gemini pulled the .glb from GitHub, App.D.2) shifts results across machines and months (§3.3).
  • Graded coverage — a binary verdict cannot say whether the ball, the state, or the transition is missing (§3.4).

Contamination and aging. Only Dev (200 tasks) ships contracts; Core, Extended, Robust are hidden (Tab.6). Tasks are original designs, not tutorial reproductions (App.B.3), but seeds were LLM-expanded (§2.2) and Rendering is easy because RawShaderMaterial/EffectComposer idioms were absorbed in pretraining (§4.2); Robust’s re-randomization blunts that (§2.3). Frozen Three.js version: not reported. Nine models at May-2026 rates date the economics (§4.1, Tab.8). Contract human agreement: not reported.

Task construction, splits, and anti-leakage
  1. Expert seeds — Five PhD researchers in 3D graphics and interactive systems spent two months hand-crafting peer-reviewed seed tasks; seeds are templates for task families, not an evaluation split (§2.2 Stage I).
  2. Expand and filter — LLM-assisted expansion to over 10,000 candidates across layouts, mechanics, and effects; annotators discard ambiguous, trivial, underspecified, or non-operationalizable ones (Stage II).
  3. Verify and contract — Survivors run in a headless browser to confirm asset availability, stable loading, and interface compatibility; experts author affordances, reachable states, action-driven transitions, and assertions with numeric tolerances; unstable tasks are discarded (Stage III).
  4. Harden and hide — Inject defects into validated implementations and keep a contract only if it rejects every mutant (§3.2); contracts stay out of prompts and leaderboard releases; Robust variants perturb constants, counts, initial states, and assets (Stage IV).

Composition (Tab.4, Tab.5): 2,026 canonical tasks; Simulation 649, Rendering 620, Application 757 across 15 domains; six difficulty levels D1–D6; three asset tiers. Core is a 205-task hard subset selected for low reference-model T-Cov: 63 Simulation / 47 Rendering / 95 Application, 164 tasks (80.0%) at D5–D6, 25 (12.2%) needing .glb assets, 73 shared asset files; D1/D2 were removed by the bottom-T-Cov sampling (App.B.2). Splits (Tab.6): Core 205 hidden; Extended 1,621 hidden, meant for lower-variance comparison; Robust 615 hidden — three variants per Core task with physical constants, object counts, initial states, prompt phrasing, and .glb filenames randomized and the contract rewritten per variant (§2.3); Dev 200 public with contracts and reference outputs. Anti-leakage (App.B.3): contracts never appear in prompts; different parameter instances reference different asset files; per-variant randomization; original designs rather than tutorial reproductions; hidden-split contracts and references kept private. Correctness is behavioral, not tied to one reference HTML: any implementation whose runtime states satisfy the contract passes (§2.2). The sandbox is network-locked so generated pages cannot fetch remote scripts (App.E).

P253 in full, and five ways to fail it

The brief (Listing 1, App.D.2) fixes the scene: camera at (0, 5, 15); an orange torus hoop at (0, 8, −8) with inner radius 0.6; a 2.5 × 2 × 0.1 backboard at (0, 9, −8.5); a ball of radius 0.35 starting at (0, 3, 10); BarramundiFish.glb loaded with GLTFLoader, scaled (2, 2, 2), placed on the backboard as a mascot and stored as window.__fishModel. Physics: gravity −9.81, fixed 1/60 s timestep, vy = power * sin(angle), vz = -power * cos(angle); a score when the ball passes within 0.6 horizontally and 0.3 vertically of the hoop centre; backboard reflection multiplies z-velocity by −0.5; floor bounce at y <= 0.35 with vy *= -0.4 and horizontal velocities scaled by 0.8; the ball stops below speed 0.1. Particles: 100 gold on score fading over 2 s, 20 white smoke on launch fading over 0.5 s. Controls: hold SPACE to charge power 0→20 over 2 s; UP/DOWN for angle 30–75°; LEFT/RIGHT for aimX in [−3, 3]; ENTER launches; R resets; the fish spins and bounces for 2 s on a score. HUD element ids: scoreDisplay, shotsDisplay, powerBar with inner powerFill, angleDisplay, aimDisplay, statusText. Required window.__3D_STATE__ fields: phase (charging | aiming | ready | flying | scored | missed | idle), power (0–20), angle (30–75), aimX, score, shots, ballPosition {x, y, z}, ballVelocity {x, y, z}, isCharging, particleCount, fishLoaded, fishCelebrating, ballSpeed, lastShotResult (none | score | miss); initialized idle, power 0, angle 45, aimX 0, score 0, shots 0.

The hidden contract probes that phase advances idle → charging → flying → scored/missed on the correct action sequence, that ballVelocity matches the expected projectile trajectory, and that score, shots, and lastShotResult stay synchronized. Five outputs, five distinct failures (App.D.2, Fig.9–10): Claude Opus 4.6 requests the .glb from a relative path that does not match the task layout; Gemini-3.1-Pro-Preview bypasses the asset directory and fetches from an external GitHub raw URL, breaking sandbox isolation; GPT-5.4 parses the prompt cleanly but never renders the scene; DeepSeek-V4-Flash loads the asset but omits window.__fishModel; Qwen3.6-Plus renders and plays but advances physics with clock.getDelta() rather than the fixed 1/60 s step, so the trajectory is frame-rate dependent and the hoop-pass test fires at the wrong moment. Every one looks correct in the rendered frame and surrounding HTML. (The listing labels difficulty “L5” where the rest of the benchmark uses D1–D6.)

Per-model paradigm scores (Tab.13): DOM τb −0.238, VLM +0.143, Agent +0.048; DOM ranks DeepSeek-V3.2 (V-Cov 21.9) at 54.7 above GPT-5.4 (27.8) at 50.0, and DeepSeek-V4-Flash, second-weakest by V-Cov, receives the highest Agent score. Per-domain economics (App.C.3, Fig.8): the two DeepSeek models peak at ∼$22,000–$33,000 of labor per API dollar versus ∼$2,000–$6,600 for the other five; GPT-5.4 and Gemini lead per-domain TEM (∼140–150× peaks versus ∼40× for DeepSeek); Materials, Shaders, and Postprocess are top-5 on both metrics for every model, and Complex System, Creative, and Graphics are near-zero RoA for every model.

Main result

On WorldCoder-Core the best system, GPT-5.4, reaches 27.8% V-Cov; the top four cluster at 23.0–27.8%, and the open-weights gap is 2.5 points (Qwen3.6-Plus 25.3%). (Tab.1) Coverage roughly halves per layer — A-Cov 40.6–67.4%, S-Cov 30.7–46.1%, T-Cov 15.8–26.3% (§4.2): objects exist, states are reachable, transitions fail. On P253 five models fail five ways — bad asset path, remote fetch, no render, missing window.__fishModel, frame-rate-dependent physics — all invisible to a screenshot (App.D.2). Each number is one zero-shot run per task; seeds, repeats, and confidence intervals are not reported (§4.1), so the 1.3-point GPT-5.4/Gemini gap reads as a tie.

Key findings

  • No external judge recovers the ranking: DOM-only inspection has τb −0.021 and a 33.7% false-pass rate at unit cost; Screenshot+VLM (GPT-5.4) has τb −0.068 at ∼50×; the 8-step inspection agent alone correlates positively (+0.111) yet passes 45.6% of worlds with V-Cov below 30, at ∼400×. (Tab.2) Per model, DOM inverts the order (τb −0.238, Tab.13).
  • State Schema Drift (42.8%) and Broken Interaction Chain (40.8%) make up 83.6% of zero-T-Cov records; Physics Violation is 0.4%, Semantic Misunderstanding 2.7%. (§4.5, Tab.14) Models understand the brief; they expose wrong field names or never wire handlers to state (Drift 93–98%, Chain 88–98% per model).
  • Perturbing constants, counts, and asset names drops GPT-5.4 to 19.9% and Qwen3.6-Plus from 25.3% to 13.5%, widening the proprietary–open gap from 2.5 to 6 points. (Tab.3) Template recall, not mechanism understanding.
  • Rendering is easiest (shaders up to 60.5% for Gemini, materials 54.8% for GPT-5.4) and Application hardest (game 5.0–12.8%); creative is 0.0% for every model. (Tab.12)
  • System-level failures separate models more than behavioral ones: DeepSeek-V4-Flash crashes on 42.4% of tasks, Kimi-K2.5 omits the state object on 10.2%, median completion tokens span 5,418–15,843. (Tab.11)
  • Utility inverts capability: DeepSeek-V4-Flash tops RoA at $19,150 per API dollar (30× any proprietary model); GPT-5.4 wins TEM at 68.9× via top coverage and lowest latency (88.1 s/task); the top 5 of 15 domains carry 55–65% of TEM. (Tab.1, Fig.6)

Implications

For interactive programs the checker must read state from inside the program; once it does, DOM, screenshot, and agent judges prove rank-inverting, not merely noisy (Tab.13) — a caution for LLM-as-a-judge and agent-as-a-verifier on canvas-rendered artifacts. We sit downstream of Design2Code, ArtifactsBench, and WebGen-Bench (outside-in page judges) and beside GameDevBench and V-GameGym (Godot, Pygame) (App.A). Dev’s 200 public contracts are a reusable programmatic ground truth; since schema drift appears in 96% of zero-T-Cov records (Tab.14), one small fixed interface may beat per-task schemas; and what we did not build — a program-owned action API (our probes are DOM events and key presses), host-controlled randomness, generation-time checks the model can run itself, and a repair loop fed by the CHECK_FAIL trace (ours is single-shot) — is where the next system starts.

Limitations

We know Core, Extended, and Robust cannot be independently re-verified: contracts are hidden, only Dev’s 200 are public, and the repository is anonymous at preprint time (Tab.6). We did not separate interface non-compliance from behavioral error: a correct world with different field names fails as State Schema Drift, so V-Cov partly measures instruction following (§4.5). We did not report human agreement on contracts, run-to-run variance, or confidence intervals; RoA/TEM rest on seven expert time estimates (median 4.7 h) plus a difficulty fallback, and failure modes were labeled by an LLM grader (§4.1, App.C.1, App.D.1). Coverage is uneven: Robust reports five of nine models, the paradigm comparison seven, and Tab.11’s caption excludes Kimi-K2.5 and MiniMax-M2.7 from RoA/TEM for low report coverage, yet their values are printed.

Critiques and Questions

  1. Mutation-hardening guards against slack contracts, not over-strict ones, and the mutants come from the team that wrote the contract; without human agreement, a correct-but-different world can still fail an assertion written against one reference.
  2. The tables disagree: Tab.13 lists DeepSeek-V4-Flash at V-Cov 19.9 where Tab.1 says 16.5 (Qwen 25.4 vs 25.3), and App.A.2/Fig.5 describe a window.__SCENE__ interface, a “Scene Interaction Graph,” and E-Cov/P-Cov metrics the main text never defines. Which protocol produced the numbers?
  3. Extended’s 1,621 tasks exist for lower-variance comparison (§2.3), yet no Extended result appears; a 1.3-point gap on a single-run, 205-task leaderboard is the whole ranking evidence.
  4. Cost is normalized to DOM (StateProbe ∼2×) without absolute figures, and ∼400× depends on the agent’s 8-turn budget; the VLM judge’s 2.7% pass rate looks like miscalibration, not blindness — per model it correlates best (+0.143, Tab.13).
