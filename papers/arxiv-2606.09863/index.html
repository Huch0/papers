Curated byChiyeong Heo

A two-benchmark diagnostic study of false success in LLM agents: it is a large share of failures (45–48% in single-control tau2-bench domains, 75.8% among self-assessing AppWorld failures), LLM judges cannot detect it (no configuration beats AUROC 0.65 on tau2-bench, 0.54 on AppWorld) because they anchor on the very surface proxies false success produces, and cheap TF-IDF classifiers detect it far better (task-disjoint AUROC 0.83 / 0.95, roughly 3,300× faster).

This is the motivation-critical evidence TDE leads with: it quantifies exactly the failure TDE exists to close — agent self-reported completion is false for 75.8% of self-assessing failures on AppWorld, TDE’s planned testbed — and shows LLM-judge adjudication cannot patch it (AUROC ≤ 0.65 / ~0.54 even with the ground-truth task spec), while the one dual-control environment with independent state verification suppresses false success to 3% of failures. It is a citation ally, not a novelty threat: a diagnostic study plus surface-pattern triage detectors, whose own conclusion is that high-stakes deployment needs direct trajectory–environment consistency checks — precisely the mechanical, environment-evaluated acceptance suite and red–green completion gate TDE proposes; the paper measures the disease and explicitly leaves TDE’s cure unbuilt.

Motivation

LLM agents fail silently by confidently reporting completion when the environment state says otherwise — an airline agent announces a processed refund that no database records. Unlike a crash, refusal, or hand-off, nothing surfaces until downstream damage accumulates, so the authors frame it as a monitoring problem, not a benchmark curiosity (§1). Prior work leaves this specific mode uncovered: benchmarks with programmatic rewards label failures but do not analyze the agent’s completion claim; failure-localization work (Who&When, AgenTracer, AgentDebug) assumes the failure is already identified; and the standard monitor — an LLM judge reading the trajectory — rests on the untested assumption that a capable model can tell whether another model finished the task (§2).

Contribution (what’s new)

The genuine delta is a mechanistic account plus a text-independent replication, not a method for agents. False success has a consistent behavioral surface signature, and that signature is exactly the proxy LLM judges use to infer completion — confident closing language in tau2-bench, action-sequence volume in AppWorld — so judges are structurally anti-correlated with truth (FS vs HF AUROC 0.18–0.30), while a discriminative classifier trained against ground-truth labels learns the same surface signal in the opposite direction (§4.3, Contribution 3). Supporting deltas: a labeled tau2-bench corpus of 616 false successes with human-validated three-class labels (κ = 0.86); a circularity-free AppWorld replication where labels come from the agent’s structured status database write and features from API-call sequences, with zero text overlap (§3.2–3.3); and evidence that environment structure moderates the failure: dual-control verification coincides with an order-of-magnitude suppression (3% vs 45–48% of failures) (§4.1). Because judge failure is shown to be mechanistic (anchoring), not informational — handing the judge the full ground-truth spec does not help — the monitoring fix must be discriminative or structural, not better prompting.

Research questions

(1) How prevalent is false success across models, domains, and agent architectures, and what moderates it? (2) Can LLM judges detect it, and if not, why exactly? (3) Can lightweight discriminative detectors do better, and how far do they generalize (cross-model, cross-domain, cross-task, cross-time, under adversarial rewrites)?

Methodology

Two corpora with language-independent ground truth. From the public tau2-bench leaderboard: 9,876 trajectories from 8 frontier model families (8,146 reward=1, 1,730 failures); failure closing messages are regex-classified into false success (616), honest failure (753), or ambiguous (361), validated on 200 human-labeled cases. From AppWorld: 8,190 released trajectories from 4 model families, restricted to the two self-assessing architectures (full_code_refl, ipfuncall) that ever write status=fail, yielding 1,879 failures with explicit completion claims (1,425 FS / 454 HF) — labels from the status field, features from API-call sequences only. Three detectors (TF-IDF + logistic regression, TF-IDF + XGBoost, DeBERTa-v3-base) are evaluated under random, leave-one-model-out, leave-one-domain-out, and task-disjoint splits, against 5 LLM judges under 5+ prompt conditions.

Method details
  1. tau2-bench three-class labeling (§3.3, App.A) — Regexes over the closing message: an assertion set (successfully, has been ..., refund of $N, all set) vs an honest-failure set (I cannot, transferring to a human, shall I proceed). FS if only assertion matches, HF if only failure matches, ambiguous otherwise. Human validation on 200 stratified trajectories: 91.5% agreement, κ = 0.86 (per-class 92% FS / 91% HF); GPT-5 as annotator agrees only 83.5% (κ = 0.71) — below the regex pipeline.
  2. Circularity controls (§3.3, App.G) — Masking the top-30 regex trigger tokens from the TF-IDF vocabulary changes random-split AUROC by 0.001 (0.940 to 0.939); training with the closing message removed still reaches 0.924 (vs 0.934 closing-only, 0.932 full trajectory); and the AppWorld replication has zero overlap between label source (DB field) and features (API tokens).
  3. Detectors (§3.4, App.C) — Bigram TF-IDF (30k features, sublinear TF) into class-balanced logistic regression (~1 ms/trajectory) or XGBoost (300 trees, depth 6); DeBERTa-v3-base (184M, 512 tokens, left-truncated to keep closings, 3 epochs, single seed). AppWorld trajectories are serialized as method-endpoint token strings, e.g. GET amazon cart.
  4. Judge evaluation (§3.5, App.D) — tau2-bench: 295-trajectory stratified set (~95 FS / 105 TS / 105 HF); 5 judges (GPT-4o, Claude Sonnet 4.5, Llama 3.3-70B, DeepSeek-R1, o3-mini) × 5 conditions (blind, no-closing, checklist, tool-only, stepwise) + strong-real, which prepends the actual ground-truth task spec. AppWorld: 200-trajectory set (100 FS / 100 HF), 3 judges × 3 conditions incl. a checklist stating GET-only sequences cannot complete write tasks. Judge output (completed, confidence) is converted to an FS score; temperature 0.0, cached.
  5. Metrics — AUROC on FS vs TS for tau2-bench (Frame A, the deployment question), FS vs HF for AppWorld (no TS class in its eval set); FS vs HF on tau2-bench is Frame B, used to expose the judge mechanism. Task-disjoint = GroupShuffleSplit over task id, 5 seeds - the cleanest generalization estimate.

Main result

Across every judge, prompt, and phrasing — including the strong-real condition that hands the judge the ground-truth task specification the agent itself never saw — no tau2-bench judge configuration exceeds AUROC 0.65 (best single cell: Sonnet 4.5 no-closing, 0.640; strong-real moves Sonnet to 0.632) (Tab.5, p.8), and the best AppWorld judge reaches 0.537 (GPT-4o with the checklist hint), while Claude Sonnet 4.5 degrades as context is added: 0.368 blind → 0.289 with task → 0.274 with checklist (§4.3, Fig.4). The lightweight detectors sit far above: task-disjoint AUROC 0.849 (LR) / 0.825 ± 0.025 (XGBoost) on tau2-bench and 0.953 ± 0.020 (XGBoost) on AppWorld, with the 184M DeBERTa within 0.03 of the linear model on both (Tab.4, p.6). In deployment terms, at a 10% flag rate the detector recovers 72% [95% CI 63–80] of false successes vs the best judge’s 13% [8–17], at 1.19 ms vs ~4,000 ms per call (~3,364×) (Tab.6, Fig.6, p.9-10).

Key findings

  • Prevalence is universal but model-dependent: 13% (GPT-5.2) to 79% (Qwen3-Max-Thinking) of failures on tau2-bench, 67–89% on AppWorld — and reasoning is not protective (Fig.1, §4.1): the top offender is a reasoning model whose <think> traces rationalize why the action should have succeeded rather than verify state (averaging 1,274 characters in FS cases vs 486 for other models).
  • Environment structure moderates the failure mode: 3% of failures in dual-control telecom vs 45% / 48% in single-control airline / retail (§4.1) — the authors explicitly downgrade this to a hypothesis (one dual-control domain, only 15 FS cases), but it is the paper’s most structurally important observation: independent verification appears to suppress false success by an order of magnitude.
  • On AppWorld the behavioral mechanism is directly legible in the features: false success = read-heavy sequences that never write state before claiming done (e.g. repeated GET venmo transactions); honest failure = write-retries and post-completion restarts (e.g. POST supervisor message followed by GET supervisor profile, coefficient −4.81) (Fig.3, §4.2) — agents that recognize failure behave differently at the action level.
  • Task difficulty inverts the effort signature: FS rate falls with difficulty (88.2% → 76.0% → 70.1%), and on easy tasks FS agents make fewer calls than HF agents (23 vs 37) but on hard tasks more (51 vs 34) (§4.1) — easy-task false success is premature capitulation, hard-task false success is extended exploration ending in a false claim.
  • The judge failure is directional, not noisy: on FS-vs-HF (Frame B) all 25 judge × condition cells score AUROC 0.18–0.30 — below chance — and assertion-language trajectories are scored 0.27–0.36 more completed than honest-failure ones regardless of actual outcome (§4.3, Fig.5), an effect that survives removing explicit honest-failure markers (0.14–0.32).
  • Detector generalization has clear boundaries: cross-model LOMO holds at 0.913 / 0.856 (tau2 / AppWorld), but cross-domain LODO drops to 0.665–0.696 (vocabulary-specific; 50–100 labeled examples per class recover LR to 0.788–0.827), cross-temporal tau-v1 → tau2 is 0.68–0.73, and adversarially rewriting honest-failure closings in confident style flips the detector on 20% and judges on 24% of cases (Tab.4, Tab.13, App.H).

Implications

For monitoring practice: use lightweight, domain-calibrated classifiers as triage signals and stop trusting LLM judges as the primary monitor for false success — the judge can be told what to look for and still cannot find it. For evaluation methodology, the paper’s own end-state is the sharpest implication: at a 10% flag rate detector precision is only 50%, so neither detectors nor judges suffice autonomously; substantial gains “would likely require methods that verify trajectory-environment consistency directly rather than reading surface text” (§4.4, §5) — i.e. the paper measures the problem and points at mechanical state verification without building it. That is the TDE opening: environment-evaluated acceptance suites over final world state are the direct-consistency check this paper calls for, and the telecom dual-control observation is field evidence that such verification structurally suppresses the failure mode rather than merely detecting it. Lineage: it complements Cao et al. 2026’s “corrupt success” (reward=1 trajectories with procedural violations — a disjoint population from reward=0 false success), sits downstream of tau-bench / tau2-bench (Yao et al. 2024; Barres et al. 2025) and AppWorld (Trivedi et al. 2024), and gives mechanistic teeth to the judge-reliability concerns of Thakur et al. 2025 and the agent-as-judge line (Zhuge et al. 2025). Testing the dual-control hypothesis causally across multiple environments — the closest thing to an ablation of TDE’s core premise that exists in the wild. Whether frontier coding agents (the AppWorld corpus is GPT-4o / GPT-4-Turbo / LLaMA-3 / DeepSeekCoder era) show the same 75.8% rate.

Limitations

  • Both corpora are structured-API benchmarks with programmatic rewards; whether false success extends to web navigation, open-ended code generation, or scientific reasoning is explicitly open (§5).
  • The headline 75.8% applies only to a subset: two self-assessing AppWorld architectures, excluding 3,120 no-status trajectories and the two architectures that always write status=success (whose FS behavior is unmeasurable by this labeling) (§3.2, App.F).
  • Detectors are triage-only and brittle: 50% precision at a 10% flag rate, domain-specific vocabulary (LODO 0.665–0.696), temporal drift (0.68–0.73), and 20–25% flip rates under confident-style rewrites of honest failures (§5, App.H).
  • The dual-control suppression rests on one domain with 15 FS cases and is confounded with other telecom differences — the authors flag it as a hypothesis, not a causal claim (§4.1).
  • Inferred: trajectories come from public leaderboard / released experiment outputs, so per-model FS-rate comparisons inherit uncontrolled task mixes and submission selection effects, with no confidence intervals on Fig.1; tau2-bench labels are regex-derived from closing text (κ = 0.86, so roughly 8–9% label noise), mitigated but not eliminated by the AppWorld replication; the tau2 judge metric (FS vs TS) and AppWorld judge metric (FS vs HF) are different discrimination problems, so 0.65 vs 0.54 are not directly comparable ceilings.

Critiques and Questions

  1. The proposed remedy inherits a weaker form of the circularity it criticizes: TF-IDF detectors still read surface patterns, not environment state — they detect the signature of false success, not its fact. The paper’s own adversarial appendix (20% detector flips) concedes this; the durable fix it gestures at (trajectory–environment consistency checking) is left entirely unbuilt, which is exactly where TDE’s mechanical acceptance suites sit.
  2. Internal number hygiene is loose: the intro says false success is 44–52% of single-control failures while the abstract says 45–48% and §4.1 says 45% / 48%; DeepSeekCoder is 89% in text but 90% in Figure 1; zero-shot LODO is 0.696/0.665 in Table 4 but 0.693/0.657 in Table 13. Nothing load-bearing changes, but exact citation requires choosing a source (Table 1 / Table 4 values are used here).
  3. Is 75.8% an overestimate of the deployable risk? Restricting to architectures that ever write status=fail selects for agents whose status field is meaningful, but also drops the majority of AppWorld trajectories; the react/plan-exec populations (always-success) arguably represent an even worse silent-failure regime that the labeling cannot see.
  4. The Frame A eval set is 295 trajectories and AppWorld’s is 200 — small enough that judge-ranking differences (e.g. Sonnet 0.640 vs GPT-4o 0.545) carry meaningful sampling noise; no CIs are reported for judge AUROC cells.
  5. Single-author study with single-seed DeBERTa training; the detector conclusions are robust to this (linear models match anyway), but the judge-mechanism claims rest on three judges’ anchoring gaps without significance testing.
Why do LLM judges score below chance (AUROC 0.18-0.30) at separating false success from honest failure on tau2-bench, even when given the ground-truth task specification?
Because they anchor on confident completion language as their evidence of success. False-success trajectories produce exactly that language while honest failures contain explicit inability or hand-off language, so judges systematically rank false successes as more completed than honest failures - a directional inversion, not noise. Extra information does not change the heuristic: the strong-real condition moves Sonnet 4.5 from 0.640 to 0.632, and on AppWorld more context makes Sonnet worse (0.368 blind to 0.274 with checklist).
